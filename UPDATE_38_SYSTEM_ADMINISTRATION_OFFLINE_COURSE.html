What you will learn

Identify the responsibilities of someone who keeps a computer useful, secure and recoverable.

Why this matters

A system administrator keeps computers and services dependable for the people who rely on them. That may mean setting up an account for a new colleague, explaining why an application will not launch, checking whether a disk is nearly full, confirming that a backup can be restored, or investigating unusual activity. A household computer needs the same principles on a smaller scale. A school computer room, a charity office and a bank apply them to more people and higher consequences.

Administration is not the same as programming. A developer changes how software works. An administrator installs, configures, monitors and protects the environment where software runs. The roles overlap: a Umicom contributor who compiles a C23 application also needs to understand storage, permissions, running processes and logs.

A useful professional habit is to separate observation from change. Looking at free disk space is observation. Deleting old files is a change. Before a change, know what system it affects, what success looks like, how you could undo it and whether you are authorised to perform it.

Chapter 02 — Understand the computer, operating system and user account

What you will learn

Explain hardware, the operating system, applications and accounts as separate layers.

Why this matters

A computer has physical components such as a processor, memory, a drive and a network interface. The operating system coordinates these components and supplies standard services. Applications use those services to open files, display windows, send network requests and use memory. Your user account controls the identity and permissions under which an application acts.

It helps to picture the layers from bottom to top: hardware, operating-system kernel and drivers, operating-system services, applications and the person using them. If a text editor cannot save a document, the cause may be inside the editor, a directory permission, a full drive or a read-only file. One symptom can have several possible causes.

Windows and Linux organise these concepts differently. Windows normally shows drives such as C: and uses backslashes in paths. Linux usually presents a single directory tree rooted at /. Neither choice tells you whether a file is safe to delete. Always inspect the actual path and ownership first.

New words, explained

Term Plain-English meaning
CPU Processor that executes instructions.
RAM Working memory used while programs run.
Storage Persistent space for files and installed software.
Kernel Privileged part of the operating system that controls hardware and processes.
Account Identity whose access rights are checked by the operating system.

What you will learn

Identify the program you have opened before typing unfamiliar commands.

Why this matters

The screenshot below is from the supplied Windows search example. It shows why the programme name and version matter more than the colour of the icon.

The Start menu can show Windows PowerShell, Windows PowerShell ISE, PowerShell and Developer PowerShell for Visual Studio. They are not identical products. Windows Terminal is the tabbed terminal application. It can host different command-line shells. PowerShell 7 is a modern shell normally launched using pwsh. Windows PowerShell 5.1 is the older Windows-included shell, normally launched with powershell.exe. CMD runs Command Prompt commands, which sometimes resemble PowerShell commands but do not share all syntax.

Your screenshot illustrates this confusion well: it shows several similar blue terminal icons in the Windows search results. To avoid mistakes, use the program name and verify the running version inside the shell. Windows PowerShell can be useful for installing PowerShell 7 when the latter is not yet available. There is no need to open a privileged shell for the exercises in this course.

A terminal window is a way to communicate with the shell. The shell reads a command, invokes a built-in operation or an external program, and displays the result. A command is not automatically a script. We use individual interactive PowerShell commands for learning and administration; all new Umicom executable implementations remain in C23 or Assembly.

What you will learn

Understand the pieces of a command and find trusted documentation.

Why this matters

A command normally contains a command name followed by arguments or options. In Get-ChildItem -Path "$HOME", Get-ChildItem is the operation and -Path is the name of a parameter. The quoted folder is the value of that parameter. In git --version, --version is an option recognised by Git, not a PowerShell parameter. Different programs have different option styles.

PowerShell commands are called cmdlets when they follow the verb-noun naming convention, such as Get-Process and Test-Path. It also runs native executables such as git.exe and cmake.exe. A vertical bar | passes output to another command; you can use it to select columns rather than read pages of detail.

Before using an unfamiliar command, prefer Get-Help, the program’s --help output and its official documentation. Treat copied commands from chats and websites as proposals to review, not instructions to execute blindly. If an option looks like it deletes, formats, force-pushes or rewrites history, do not execute it during a beginner exercise.

New words, explained

Term Plain-English meaning
Parameter Named input to a command, such as -Path.
Argument A value passed to a command or executable.
Pipeline A connection that passes command output to another command.
Alias An alternate name, such as pwd for Get-Location in PowerShell.
Exit code A number indicating whether a native program succeeded.

What you will learn

Create a private training directory and understand absolute and relative paths.

Why this matters

A folder groups files and other folders. The working directory is the location where relative paths are interpreted. An absolute Windows path such as C:\Users\Alex\UmicomLearning identifies a location without depending on where you started. A relative path such as notes\README.md begins inside the current directory. You can get unexpected results if you change files while standing in the wrong location.

We deliberately use $HOME\UmicomLearning for examples. $HOME is your account’s personal home folder, so the exercise does not touch your real C:\umicom\Umicom-Applications workspace or require administrator privileges. $HOME expands to a path that can contain spaces; the quotation marks keep that path together.

Get-Location and pwd observe the current directory. Set-Location and cd change it. New-Item -ItemType Directory creates a folder. Test-Path checks whether one exists. Do not use git submodule add as a synonym for creating a regular folder: it registers a separate Git repository and needs more careful review.

What you will learn

Create a Markdown note, read its contents and recognise file extensions.

Why this matters

A text file stores characters. A Markdown document (.md) is plain text with conventions for headings, links and lists. A C source file (.c) is also text but is interpreted by a compiler rather than a documentation renderer. A word-processing document (.docx) uses a different structured format. System administrators frequently inspect configuration and log files, so distinguishing these formats matters.

In the practice folder, use Notepad to create a short README.md. You do not need to write a PowerShell script to make this file. You can also write a short line interactively using Set-Content. However, the course does not create .ps1 or Python implementation files.

PowerShell Get-Content displays a text file. Get-Item reports file metadata such as size and modification time. Get-FileHash calculates a fingerprint used later when learning backup verification. Opening a text document is normally a reversible, low-risk activity, but opening an unknown executable or script is not equivalent.

What you will learn

Identify the layers involved when a computer connects to a website or service.

Why this matters

A network connects devices that exchange messages. An IP address identifies a network interface in the relevant routing context. A router forwards traffic between networks. Diagnostics should favour observation and approved destinations. This chapter uses public documentation domains as examples but does not imply that they are always reachable from every network. Avoid scanning arbitrary hosts or internal services unless you have permission.

Instructor guide — System Administration From Zero

Purpose: Deliver a technically accurate introduction to learners who may have never used a command line. Do not dilute technical accuracy, and do not rush ahead when foundational terms are not yet understood.

Before class

  1. Prepare a Windows 10/11 machine with a standard account and a Linux machine or authorised VM. Verify the shell versions with each learner.
  2. Offer a text-based version of every image and read out the command before demonstrating it.
  3. Demonstrate the difference between the command and the example output. Never expect a learner to type the PS C:\...> prompt.
  4. Agree on a private practice folder in each learner's home directory; do not use real Umicom repositories for experiments.
  5. Ensure optional software installations are authorised. Where they are not, do the chapter as a read-only demonstration.
  6. Never ask learners to share tokens, passwords, patient data, private account numbers or sensitive logs.

A repeatable 40-minute teaching pattern

  • 5 minutes: Explain the problem the new idea solves, with one realistic example.
  • 8 minutes: Draw or inspect one simple diagram; define unfamiliar words.
  • 15 minutes: Demonstrate the commands slowly, one by one. Ask learners to check the result after each step.
  • 7 minutes: Let learners repeat the steps and explain what they observed; support different screen readers and terminal font sizes.
  • 5 minutes: Review failures, explain when a result is unverified, and connect the topic to Umicom.

Accessibility and age inclusivity

Use plain, professional language. Explain a term before using its abbreviation. Pair images with text alternatives. Do not assume that learners own administrator credentials, a powerful laptop or a paid development tool. Allow learners to complete Windows or Linux variants as appropriate. A competent adult returning to study and a young learner both deserve precise instruction.

Safety boundaries

Practice never requires privileged system changes, public GitHub publication, force-push, recursive deletion, mass software upgrades or live financial execution. The person teaching decides whether an installation or remote account operation is permitted. Stop when an instruction does not match the learner's platform.

Practical differentiation

  • A learner with no previous experience should work through Chapters 1–8 and practise pwd, Get-Location, Get-Content and file previews.
  • An experienced Windows user can compare PowerShell and Linux administration commands while explaining identity and privilege.
  • A software engineer can complete the optional C23 lab and describe why the educational inspector cannot replace Umicom Framework file services.

Assessment

Use the workbook. Ask learners to provide the command, expected result, actual result, interpretation and one precaution. Distinguish PASS, NEEDS HELP and NOT RUN. Do not require screenshots of personal account identifiers.
