## 1. Build Framework Education (Windows UCRT64)

In PowerShell:

```powershell
Set-Location "C:\umicom\Umicom-Applications"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"

cmake -S ".\framework\tools\umicom-education" `
    -B ".\build\umicom-education" `
    -G Ninja `
    -DCMAKE_C_COMPILER="C:\msys64\ucrt64\bin\gcc.exe" `
    -DBUILD_TESTING=ON

if ($LASTEXITCODE -ne 0) { throw "Umicom Education configure failed" }

cmake --build ".\build\umicom-education" --parallel 2
if ($LASTEXITCODE -ne 0) { throw "Umicom Education build failed" }

ctest --test-dir ".\build\umicom-education" --output-on-failure
if ($LASTEXITCODE -ne 0) { throw "Umicom Education tests failed" }
```

Expected: **30 registered tests** pass (28 retained, 2 new). The new checks are `framework.education.device_io_trace` and `framework.education.device_io_trace.cli`.

To run only the new test pair:

```powershell
ctest --test-dir ".\build\umicom-education" `
    -R "^framework\.education\.device_io_trace" -V
```

Run the native inspector on its deterministic fixture:

```powershell
$Education = ".\build\umicom-education\bin\umicom-education.exe"
$Fixture = ".\build\umicom-education\education-device-io-test\fixture with spaces\driver requests.dio"
& $Education device-io-trace --file $Fixture
```

The expected report begins with `Device I/O trace: 27 records`. It reports five submissions, five completions, one cancellation request and five reaped results. The test fixture is generated by CTest; it does not describe physical device activity.
