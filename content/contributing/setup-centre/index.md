# Contribute to Umicom Setup Centre

![Umicom Foundation](../../assets/branding/umicom-wordmark.svg){ .umicom-wordmark .umicom-wordmark-light width="215" }
![Umicom Foundation](../../assets/branding/umicom-wordmark-on-dark.svg){ .umicom-wordmark .umicom-wordmark-dark width="215" }

You can practise changing a Setup Centre review without downloading an image, opening a virtual machine or touching a disk. Use a local Framework checkout and a text editor. If you have a C23 development terminal, the last lab builds a focused test. The [user guide](../../umicom/setup-centre-boot-planning.md) explains the available product and image choices.

1. [Describe the request in C23](01-describe-a-boot-choice.md). Follow a product, architecture and output from a spoken request to a typed record.
2. [Show the shared result in Win32](02-present-the-shared-plan.md). Read one review on the window thread and explain the exact difference between a successful review and an available workflow.
3. [Keep work and devices behind their own boundary](03-keep-review-and-work-separate.md). Draw the lives of a review, an optional worker and an opened device.
4. [Build and verify the smallest useful slice](04-verify-a-native-review.md). Check two truthful results with the existing native CLI and focused CTest.
5. [Carry an approved design into a reviewable change](05-from-design-to-accessible-ui.md). Check wording, branding, keyboard navigation and evidence for an implementation.

At the end, hand in one supported request, one refusal and a three-row evidence table. Include the exact input, output and method that produced each observation. Use the [Setup Centre contributor reference](reference.md) when you need a file path or a word explained.
