# Video narration and storyboard — LoRA aggregation, privacy and verification

**Bits to Banking · Umicom Foundation**  
**Author:** Sammy Hegab · **Format:** Narration with suggested on-screen examples.

## Opening (0:00–0:35)

“Modern language models do not learn merely because a computer answers questions. We must separate inference, model optimisation, networking and the evidence used to trust a reported result.” Introduce the lesson with the title card and a labelled distinction between implemented educational components and research proposals.

## Concept demonstration (0:35–3:00)

Display two sign-flipped LoRA factor pairs, (+1,+1) and (−1,−1). Both produce a +1 dense update. Average the factors to show the incorrect zero result, then aggregate the actual effects. Explain source permissions, leakage from shared gradients, robust aggregation and the separate meanings of checkpoint identity, execution compliance and model usefulness.

## Worked exercise (3:00–5:00)

Pause on the equation or diagram. Invite the viewer to calculate a result independently. Reveal the expected numerical value and define every input, output and unit. Point to the Framework-owned C23 laboratory when a native implementation exists; otherwise label it as a thought experiment.

## Verification and limitations (5:00–6:15)

Explain that code compilation, numerical parity, source authentication and model-quality evaluation are different evidence types. Where proof, consensus, privacy or production-scale performance has not been independently established, say so explicitly.

## Closing task (6:15–7:00)

Write one falsifiable claim, name a trusted baseline and design a deliberately invalid input. Read the related numbered lesson and the cited primary paper rather than relying on promotional headlines.
