# Stake-Weighted Votes and Finality — narration and storyboard

**Bits to Banking · Umicom Foundation**  
**Script author:** Sammy Hegab · **Licence:** MIT

## Sequence and narration

**Scene 1.** 0:00–1:10 — Introduce public proof-of-stake using locked economic weight. Validate that “number of validator keys” differs from “amount of effective stake”.

**Scene 2.** 1:10–2:20 — Work a 900-unit stake example: the numerical two-thirds threshold is 600. Ask if 630 units are enough to meet this threshold; note actual protocol conditions still apply.

**Scene 3.** 2:20–3:30 — Show why finality refers to specified checkpoint and epoch rules, not to transaction inclusion alone. A Merkle path can be valid while the enclosing block is not final.

**Scene 4.** 3:30–4:30 — Explain penalties/slashing and why cryptoeconomic assumptions do not prove source data were lawful or an AI update was beneficial.

**Scene 5.** 4:30–5:20 — Summarise: check the root, check the finality mechanism, check governing institutions and independently evaluate model quality.

## Accessibility and captions

Read all symbols aloud (including root, sequence, threshold and byte count). Put the intermediate equations into subtitles. Use distinguishable visual labels for independently authenticated facts, mathematical assumptions and conceptual examples. All figures are instructional, not real network captures or performance measurements.

## Closing prompt

Ask the learner which checks would still be missing after a successful Merkle membership proof. A satisfactory answer mentions actor authentication, authorisation, independent anchoring, ledger consensus/finality when relevant, and model usefulness evaluation.
