# Video script — From an authorised learning job to a response

**Bits to Banking · Sammy Hegab · Umicom Foundation**
**Companion:** Distributed Learning Lessons 025–030 · **Target:** 6 minutes

Introduce the three roles: coordinator, worker and independent verifier.
The coordinator holds private ticket state. The worker receives only a public
round and correlation, base-model identity, shard commitment and authorised
job limits. The verifier later checks not only bytes but policy and quality.

Storyboard: Show a source document with a red *rights not checked* label.
Move it through an approval gate before any worker access. The hash can match
and access can still be prohibited. Use synthetic records rather than real
banking or medical data in the classroom.

A native coordinator emits an assignment frame, a separate process reads it,
and a worker returns one fixed synthetic float. The codec is portable; the
files are an educational transport stand-in. When a real network is added,
trusted identities and encrypted channels must be provided by reviewed
Framework security and messaging components.

Ask learners to distinguish:
(a) a pointer to shared memory, (b) serialised bytes, (c) signed authorisation,
and (d) independently measured training usefulness. Only (b) is directly
established by the local frame exchange.

End by asking what happens after a lost acknowledgement. That is the next
lesson's replay problem.
