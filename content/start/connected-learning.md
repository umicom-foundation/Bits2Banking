# Learn from first steps to an Umicom project

Start with a piece of paper, a notes app or a conversation. The first exercises work without installing anything. Follow one path at a time and check your answer before moving on. The [technology topic map](technology-topic-map.md) helps you choose an area. The [desktop catalogue guide](../umicom/bits2banking-desktop-reader.md) shows how to open an offline course when that course has a pack.

## Give your first clear instructions

1. Open [Computing from the Beginning](../courses/computing-from-the-beginning/index.html). Follow what goes into a task, the rule someone follows, and the result that comes out.
2. In [Programming across languages](../courses/programming-across-languages/index.html), follow a short procedure on paper. Then compare names, decisions, loops and functions. You can read all the examples and run just one language.
3. Pick [Learning C](../courses/learning-c/index.html), [Learning Python](../courses/learning-python/index.html), or [Go Statement Tools](../courses/go-statement-tools/index.html). Return to the same example in **Programming across languages** when a different spelling causes confusion.
4. Look up an unfamiliar word in the [Umicom C checked integer reference](../courses/umicom-c-keyword-reference/index.html), [C23 reference](../courses/c23-keyword-reference/index.html), [C++20 reference](../courses/cpp20-keyword-reference/index.html), [Go reference](../courses/go-keyword-reference/index.html), [Python 3.14 reference](../courses/python-keyword-reference/index.html), or [Java SE 25 reference](../courses/java-keyword-reference/index.html). A word such as *for* can be shared across languages while punctuation and the order of actions differ.
5. Read the [D keyword reference](../courses/d-keyword-reference/index.html) and try the [D special-token examples](../courses/d-special-token-reference/index.html). The [D lexical specification](https://dlang.org/spec/lex.html#specialtokens) distinguishes language keywords from special tokens for information such as the compiler version and a directive for reported line numbers.
6. Read a synthetic receipt in [Practical Web and Data Foundations](../courses/practical-web-and-data-foundations/index.html) or follow a [first C# statement report](../courses/first-csharp-statements/index.html).

### Keyword reference scope

| Reference | What you can find there |
| --- | --- |
| [C23](../courses/c23-keyword-reference/index.html) | 54 primary spellings and five alternative spellings, with optional and older forms identified. |
| [C++20](../courses/cpp20-keyword-reference/index.html) | 81 reserved spellings, 11 alternate word spellings of operators, four contextual identifiers, and symbolic alternatives. |
| [Go](../courses/go-keyword-reference/index.html) | 25 reserved keywords and an explanation of how built-in names differ. |
| [Python 3.14](../courses/python-keyword-reference/index.html) | 35 reserved words and four soft keywords, including the contexts in which each soft word applies. |
| [Java SE 25](../courses/java-keyword-reference/index.html) | 51 reserved spellings and 17 contextual words, including examples of reserved forms the compiler rejects. |
| [D keywords](../courses/d-keyword-reference/index.html) and [D special tokens](../courses/d-special-token-reference/index.html) | 111 keyword-table spellings, with historical and reserved-only forms identified. The separate guide covers six special tokens and the line-number directive. |
| [Umicom C](../courses/umicom-c-keyword-reference/index.html) | Words and statements admitted by the checked integer profile, including the counted loop and the distinct one-input entry. |
| [C#](../courses/first-csharp-statements/index.html) | An introductory project with syntax and worked examples. The full keyword reference is a later course. |

Use the references to look up a word. Use the numbered courses to study complete statements and practice reading them. HTML and CSS have elements, attributes and properties with their own reference categories. The [technology topic map](technology-topic-map.md) groups them with the web lessons.

## Work from arithmetic to accounting and pricing

1. Start [Mathematics for Application Builders](../courses/mathematics-for-application-builders/index.html) with counting, parts of a whole, percentages and units. Use a ruler, a drawn number line or a simple table.
2. Continue through algebra, where a letter stands for a value, and calculus, where a rate or a running total matters. Use the exercises to check the relationship between the numbers and the units.
3. Apply the same arithmetic to [Bookkeeping from First Entry](../courses/bookkeeping-from-first-entry/index.html). Record imaginary transactions, total both sides of a journal and reconcile the balance. Use the [SQL statement workshop](../courses/sql-statement-reconciliation/index.html) when you want a database query to check the rows.
4. Open [Pricing from Cash Flows](../courses/pricing-from-cashflows/index.html). List when each promised payment arrives, compare its present value and change the assumptions to see the effect. The examples use fictional amounts and explain their model assumptions.
5. Carry that exercise into [Financial Instruments Pricing](../courses/financial-instruments-pricing/index.html), then read the [Treasury Management Systems course](../courses/introduction-to-treasury-management-systems/index.html) to see where a valuation, report and reconciliation fit.

## Choose an application project

Each exercise is an introduction or a practice enhancement. Keep examples in a learning folder with synthetic data. Start a project by recording an input, its expected result and one failure case.

| Project | Start with | A small change to plan and verify |
| --- | --- | --- |
| Umicom Studio IDE and Command | [Git and change history](../courses/introduction-to-version-control/index.html) and [Umicom development workflow](../umicom/development-path.md) | Create a small receipt-count project. Record the source path, build command, one console result and how to reproduce a missing-file error. |
| Umicom Framework and SDK | [Learning Umicom Framework](../courses/umicom-development/index.html) | Place a receipt calculation behind a small C function. Keep the window separate so the same expected result can be checked at the command line. |
| Umicom C | [Native statement calculations](../courses/native-statement-calculations/index.html) and [Building a compiler in C](../courses/building-a-compiler-in-c/index.html) | Trace one cents expression on paper and compare it with the language tool's result. Identify which characters form each name, number or operation. |
| Umicom Bank | [Bookkeeping from First Entry](../courses/bookkeeping-from-first-entry/index.html) | Show the difference between a posted receipt and a pending receipt in a synthetic summary. Check the exact rows that contribute to each total. |
| Umicom Trader and TMS | [Pricing from Cash Flows](../courses/pricing-from-cashflows/index.html) and [Treasury Management Systems](../courses/introduction-to-treasury-management-systems/index.html) | Trace one synthetic bond price into a report. Record the input rate, rounding rule and boundary result before proposing a change. |
| Umicom WebServer | [Accessible Statement Review](../courses/accessible-statement-review/index.html) and [Native web lab](../umicom/native-statement-web-lab.md) | Make a practice form readable by keyboard. Compare the displayed result with the expected value for the same synthetic input. |
| Umicom Media | [Native local AI and media](../courses/native-local-ai-and-media/index.html) | Choose an image you have permission to use. Write a resizing exercise with a known input size, expected output and watermark check. |
| Umicom LLM | [Preparing LLM training data](../courses/preparing-llm-training-data/index.html) | Make a tiny fictional dataset. Label which samples the learner can inspect while developing and which ones are reserved for checking the result. |
| Umicom Kernel and OS | [Kernel from Scratch](../courses/umicom-kernel-from-scratch/index.html) and [Umicom OS from Scratch](../courses/umicom-os-from-scratch/index.html) | Trace a small memory or boot example on paper. Record the first observable result and what an error would look like. |
| Umicom Automated Testing | [Development workflow checks](../umicom/development-path.md) and [Learning CMake](../courses/learning-cmake/index.html) | Write a repeatable check for an empty input, a valid sample and a malformed sample. Record the expected and actual outcomes separately. |

When you finish a project, return to its source lesson and write down the rule you used in your own words. Follow the next lesson or choose a linked course to see the same idea in a different project.
