# Your learning sequence

A lesson teaches one idea. A course puts related lessons in a useful order. A book collects longer reading. A lab is a practical example you can inspect and try. Start with one course; you do not need to study every subject at once.

Start at stage 1 if files, programs or commands are unfamiliar. Read at your own pace. The specialist subjects are choices after the foundations, not additional topics to learn at the same time.

## 1. Open, save and find your work

[Introduction to Computers](../courses/learning-computer-architecture/index.html). No prior knowledge. Follow its eight lessons in order.

**Ready to continue when:** You can create a folder, recognise a file, and explain input, instructions and output.

## 2. Read and write a small program

[Learning C](../courses/learning-c/index.html). Complete First programs, then Working with more information.

**Ready to continue when:** You can explain values, decisions, loops, functions, arrays, a pointer and the difference between a declaration and a definition.

## 3. Keep a history of changes

[Introduction to Version Control](../courses/introduction-to-version-control/index.html). Use a practice folder after learning to edit and save files.

**Ready to continue when:** You can describe a local change and a recorded snapshot without discarding work.

## 4. Build a small Framework application

[Umicom Framework Development: first application](../courses/umicom-development/index.html#first-application). Learn the Framework introduction, CMake, SDK use and shared activity rule as one project.

**Ready to continue when:** You can distinguish configure, build, test and run, and trace one call from its declaration to its result.

## 5. Give the same program a window

[Introduction to GTK4](../courses/umicom-development/lessons/05-introduction-to-gtk4.html). Continue with the same activity-counter project.

**Ready to continue when:** You can explain a widget, a signal and a callback, and identify the shared rule used by the window and console.

## 6. Change a feature and investigate a failure

[Build and diagnose the project](../courses/umicom-development/index.html#build-and-diagnose). Change one rule in your own practice copy; compare expected and observed results.

**Ready to continue when:** You can reproduce a problem, identify the responsible function and explain the check that should catch it.

## 7. Extend a shared service

[Framework services and application commands](../courses/umicom-development/index.html#services). Continue after the first application and diagnostic exercises.

**Ready to continue when:** You can separate reusable behaviour in Framework from application presentation, then choose one specialist topic.

## Keep your place

Follow the course contents and its Previous and Next links. The numbers in older filenames identify chapters; they do not define a single order across all subjects. Read an explanation, predict an outcome, try its exercise, and explain what happened before moving on.
