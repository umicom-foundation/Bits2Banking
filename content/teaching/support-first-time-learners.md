# Help someone take their first steps with computers

[Introduction to Computers](../courses/learning-computer-architecture/index.html) starts without programming or command-line prerequisites. The same original lessons are available as [written chapters](../lessons/00-getting-started/index.md). Use the [connected learning map](../start/systems-learning.md) to find the next subject.

## Begin with the learner's purpose

Ask what they would like to do: keep a note, understand a device, make something, or find out how software works. A small, concrete purpose gives unfamiliar words a reason to exist. Do not infer knowledge from age, occupation or how confidently someone speaks. A child and an adult may need the same first explanation, while preferring different examples.

Let the learner choose whether to read, listen, draw, speak or write. Device operation and understanding a concept are different skills. Someone who needs help typing may understand an algorithm very well. Someone who types quickly may still need an explanation of saving.

## Work through one idea together

1. Read the lesson goal aloud or in the learner's preferred way.
2. Ask what an unfamiliar word means before relying on it. Use the first explanation and the course word list.
3. Walk through the worked example. Ask the learner to predict the next result.
4. Try the paper exercise before an optional device activity.
5. Compare the observation with the prediction. Ask what changed.
6. Read the explanation after the learner has had time to answer.
7. Write down one understood idea and one next question.

An analogy explains a particular relationship; it is not a literal description of a machine. The table-and-cupboard example helps distinguish working information from a saved record. It does not explain every feature of computer memory. Name the limit of an analogy before moving to a more precise model.

## Respond to uncertainty

If the answer is unexpected, ask for the reasoning. A learner who says that a file is in memory may be thinking of the unsaved version. Find the part that is accurate before explaining a distinction. Avoid asking only whether someone understands; ask them to explain a new example in their own words.

Allow pauses and repetition. There is no required speed and no public score. Keep personal learning notes private. No learner needs to create an online account, disclose their age or publish their work to complete these foundation activities.

## Move into practical computing gradually

Before an activity on a shared device, agree on a new practice file and a folder the learner is allowed to use. Show how to return to the previous page and how to stop. Do not use real customer data, account credentials or someone else's documents as examples.

Before a command-line lab, the learner should be able to distinguish the prompt from the command, identify the working folder and explain whether the command reads or changes information. Before the OS and Kernel labs, add introductory C, arrays, functions, return values and toolchain concepts. A toolchain is the set of tools used to turn source into a program. Kernel memory work also needs pointers, bounds and lifetime.

The course introductions link those prerequisites. Return to them as often as needed. Reaching an OS source file is not a deadline, and reading source does not require installing or booting that OS.

## Writing another beginner lesson

Keep the main lesson manuscript in `content/lessons/<subject>/`. A course page belongs in `content/courses/<course>/`. Link related material instead of silently moving or replacing an older lesson.

Each new lesson should include:

- A concrete goal and explicit prerequisites, with links to explanations.
- Definitions at first use, including words inside the definitions.
- A worked example with the starting state, each action and its result.
- An exercise that can be attempted without copying an unexplained command.
- Expected observations, explained answers and recovery guidance where applicable.
- A way back to the course contents and a reason for the next learning link.

Keep examples original and state what they demonstrate. A passing hosted check does not establish a successful Kernel boot. A readable first lesson does not make the whole advanced course suitable without prerequisites. Check the actual browser and published navigation before describing them as verified.
