# Teaching system administration operations

The course supports learners ranging from secondary-school students to career changers and returning administrators. Its target is **clear professional instruction at an accessible reading level**, not simplistic programming examples. Make each conceptual term concrete with one realistic Notes or Umicom example and explicitly distinguish what is observed, inferred and unverified.

## Recommended sessions

- Session A: permissions and responsibility (Chapters 25–26).
- Session B: Windows vs Linux service operations (Chapters 27–28).
- Session C: packages, change windows and SSH trust (Chapters 29–30).
- Session D: networking and storage diagnosis (Chapters 31–32).
- Session E: restore drills and security (Chapters 33–34).
- Session F: incident evidence and capstone (Chapters 35–36, Engineering 288–291).

## Presentation method

Demonstrate how to open the correct shell. Ask learners to describe what a command will do before they run it. Execute commands **one by one**, never as an unchecked block. Show one normal outcome and one “not available/permission denied” outcome. Allow a learner without Linux or administrator access to complete an equivalent written observation.

For children, use only a supervised computer or VM. Do not require remote SSH sessions, changes to operating-system users/groups, production upgrades or access to private files. For adults, the same restrictions make the material usable in corporate training.

## Authentic work and integrity

A copy of a Notes README is an appropriate backup exercise; an actual financial or patient record is not. A green Git working tree is not an application test. A classroom C23 READY decision is not production certification. Use the workbook to reinforce these distinctions and make the practical assessment about *evidence quality*, not about memorising long command strings.
