# System Administration — Intermediate Glossary

| Term | Plain-language explanation |
|---|---|
| **ACL** | A list of rules describing who can access a file or resource. |
| **Authentication** | Checking who an account claims to be. |
| **Authorisation** | Checking whether that account may perform an action. |
| **Backup** | A recoverable copy kept separately from the original. |
| **Change window** | An agreed time to apply and verify a software change. |
| **Correlation ID** | A label linking logs from the same request or operation. |
| **Dependency** | Another service or library a program requires. |
| **DNS** | A service that translates hostnames into network address records. |
| **Host key** | The SSH server identity key verified by a client. |
| **Incident** | Unexpected behaviour requiring a controlled investigation. |
| **Inheritance** | A permission rule received from a parent resource. |
| **Least privilege** | The smallest amount of authority needed for a particular task. |
| **MFA** | Sign-in using multiple independent factors. |
| **RPO** | Recovery Point Objective: how much time-based data loss is acceptable. |
| **RTO** | Recovery Time Objective: how quickly a service must recover. |
| **Restore drill** | A controlled test that data can actually be recovered. |
| **Service** | A background program with a managed lifecycle. |
| **SSH** | An encrypted, authenticated remote-access protocol. |
| **Systemd unit** | A configuration record used by systemd to manage a resource. |
| **Unknown / Not Run** | A required check whose result is not established; never report it as passed. |

For basic terms, also see the original [glossary](glossary.md) and Chapters 1–24.
