# 50. Publish a learning website and its books together

Our educational website has two kinds of material. **MkDocs** turns the editable Markdown lessons into navigable webpages. **BookForge** processes earlier book manuscripts and creates book-specific pages and downloadable editions. Neither needs to overwrite the other's work.

This lesson builds both outputs and joins them into one website that can be checked before publication.

## 1. Understand the folders

In the Bits2Banking repository, `content/` holds the main learning-site source. `dropzone/` holds existing books, illustrations and other imported material. `site/` is generated by MkDocs; `output/site/` is generated by BookForge. The completed website keeps the original BookForge catalogue under `site/archive/books/`.

```text
content/ + mkdocs.yml ─── MkDocs ───────┐
                                        │
                                        ▼
                                     site/
                                        │
 dropzone/ ──────────── BookForge ──────┼── site/archive/books/
                                        │
                                        ▼
                                  One published site
```

The original *Islam: Blueprint for Life* chapters remain in `dropzone/documents/islam_blueprint_for_life/`. Published copies make them available through the MkDocs navigation without deleting or moving the manuscripts.

## 2. Prepare the local site

Open PowerShell and go to the repository:

```powershell
Set-Location "C:\umicom\Umicom-Bits2Banking"
```

Install the documentation dependencies into the repository's own Python environment if you have not already done so:

```powershell
py -3 -m venv .venv
& ".\.venv\Scripts\python.exe" -m pip install -r .\requirements-docs.txt
```

Existing environments do not need to be recreated. A working Python command can be checked with:

```powershell
& ".\.venv\Scripts\python.exe" -m mkdocs --version
```

To prepare the Islam volume and Umicom branding from your local Framework checkout, use the native C23 tool from the Framework build (or the existing `prepare_learning_site.py` utility). For example:

```powershell
& "C:\umicom\Umicom-Applications\build\umicom-education\bin\umicom-education.exe" `
    prepare --repo "C:\umicom\Umicom-Bits2Banking"
```

If a published copy differs from its source, review the difference before requesting a refresh.

## 3. Build both parts

First run the existing BookForge catalogue builder. It uses the Python environment in which BookForge's own requirements are installed and may also require Pandoc or other document converters for particular formats.

```powershell
& ".\.venv\Scripts\python.exe" -m pip install -r .\requirements.txt
& ".\.venv\Scripts\python.exe" .\scripts\forge_all.py
```

The catalogue should appear at `output/site/index.html`. Book editions that require an unavailable converter may need that converter installed first; do not assume an HTML build also produced a PDF.

Next build the main website:

```powershell
& ".\.venv\Scripts\python.exe" -m mkdocs build --strict
```

After a successful build, check for `site/index.html`. A `--strict` build treats documentation warnings as failures, making missing navigation targets easier to detect before publication.

## 4. Add the book catalogue to the site

Run the portal compositor:

```powershell
& ".\.venv\Scripts\python.exe" .\scripts\publish_learning_portal.py assemble
& ".\.venv\Scripts\python.exe" .\scripts\publish_learning_portal.py verify
```

The first command copies generated BookForge pages under `site/archive/books/` and places available PDF, DOCX and EPUB files under `site/archive/books/downloads/`. The second checks the new structure.

If `assemble` reports that an archive already exists, do not overwrite it unintentionally. You can review its contents and then explicitly rebuild the **generated** archive:

```powershell
& ".\.venv\Scripts\python.exe" .\scripts\publish_learning_portal.py assemble --refresh
```

This refresh changes only the generated `site/archive/books/` output. It does not rewrite `content/` or `dropzone/`.

## 5. Preview both areas

Start the native local web server, which serves the generated files without creating a second HTTP library inside Bits2Banking:

```powershell
& "C:\umicom\Umicom-Applications\build\umicom-education\bin\umicom-education.exe" `
    serve --repo "C:\umicom\Umicom-Bits2Banking" --port 8765
```

In your browser, open `http://127.0.0.1:8765/` for the learning website and `http://127.0.0.1:8765/archive/books/` for the original book catalogue. Use Ctrl+C in the terminal to stop the server.

## 6. Review the result

Check a computing lesson, an Islam chapter, the book catalogue and a downloadable book if one was generated. Confirm that the images and Umicom logo load. A working top-level home page does not by itself prove that the archive is complete.
