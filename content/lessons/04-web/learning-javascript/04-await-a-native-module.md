# Wait for a native module before enabling actions

## Loading is an operation

A JavaScript promise represents an operation whose result may arrive later. Await pauses the surrounding asynchronous work until that promise settles. It does not freeze the entire browser while a file downloads.

The activity page must wait for two operations: loading the generated JavaScript module and creating its WebAssembly instance. Only then does the exported C function exist.

## Setup recap

Follow the [browser activity lab](https://github.com/umicom-foundation/Bits2Banking/blob/main/labs/web/framework-activity/README.md) to compile C with Emscripten and serve the directory over HTTP. Read page.js in a text editor. You need no framework package from a JavaScript registry for this example.

## Trace readiness

~~~javascript
const { default: createActivityModule } = await import("./activity.js");
const module = await createActivityModule();
~~~

Import returns the module's exports. The default export is the factory generated by the build options. Calling the factory returns another promise. After both awaits succeed, the page enables its button and registers the click listener.

~~~text
disabled + Loading
   -> import module
   -> instantiate C runtime
   -> enabled + Ready
failure at either step -> disabled + explanation
~~~

The import sits inside try. A missing generated file can therefore reach catch and produce visible guidance. A static import outside this boundary would prevent the page's remaining code from running when resolution fails. The source retains that earlier form as a commented comparison.

## Lab

1. Load a complete build and check the initial and ready states.
2. In a disposable copy, remove the generated module.
3. Reload and read the visible error.
4. Restore it, then inspect the Network panel for a missing WebAssembly response.
5. Check the directory and HTTP server before changing the C model.

## Exercise and explanation

Why not enable the button immediately after starting import? A person could click before the export exists. A fast local run can hide this race. Readiness must depend on completion, not an assumed download speed.

## Beyond this lab

A product may need retry, cancellation and timeout states. Those need explicit ownership and rules for stale results. This small page has one initialization attempt; reloading starts a fresh attempt. It does not claim a complete offline installation or background update system.
