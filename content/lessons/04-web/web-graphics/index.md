# Web graphics you can explain

![Umicom Foundation](../../../assets/branding/umicom-wordmark.svg){ .umicom-wordmark .umicom-wordmark-light width="215" }
![Umicom Foundation](../../../assets/branding/umicom-wordmark-on-dark.svg){ .umicom-wordmark .umicom-wordmark-dark width="215" }

Would you still understand a monthly deposits report if the chart were unavailable? Keep the values in a readable HTML table and use pictures to make comparison quicker. In this course you will make the same report with SVG shapes and with Canvas drawing commands, then attach an icon to the link that takes readers to the data.

You need a browser and an editor. Start with [HTML links and images](../learning-html/02-links-images-and-access.md) if you have never opened the source of a page. The [monthly deposits example](../../../labs/web/web-graphics/monthly-deposits.html) uses fictional values and runs locally.

1. [Scale an SVG chart](01-scale-an-svg-chart.md). Place three bars using coordinates and see what happens when the drawing is displayed at a different size.
2. [Draw the values on a canvas](02-draw-a-canvas-from-a-table.md). Use the browser's drawing API and keep the table available when the drawing cannot run.
3. [Give an icon link a clear name](03-label-an-icon-link.md). Keep the purpose of a control understandable by text and keyboard.

Try the [guided practice](../../../simple-steps/course-guides/web-graphics.md) to compare the drawings and check the table. For graphics outside the browser, the [native graphics course](../../03-native-code/graphics-from-scratch/index.md) follows pixels from memory to a GTK4 window.
