# Follow jumps and conditional branches

## What you will learn

A program counter selects the next instruction address. Most operations advance it by one. A branch changes that order. This model has an unconditional JUMP and a conditional JZ, meaning jump if zero.

## Set up this exercise

A terminal is a window in which you type commands. A folder holds the files of a project. Install Git, CMake 3.26 or later, Ninja and GHDL with VHDL-2008 support; make their executable folders available on PATH. PATH is the list of folders the terminal searches for programs. Open a fresh PowerShell or Bash terminal and check:

~~~text
git --version
cmake --version
ninja --version
ghdl --version
~~~

Each command should print a version. If a command is not found, correct its installation or PATH before continuing. Download the Bits2Banking repository with Git if you do not already have it:

~~~text
git clone https://github.com/umicom-foundation/Bits2Banking.git
cd Bits2Banking/labs/hardware/vhdl-cpu
~~~

If you already have the repository, open its labs/hardware/vhdl-cpu folder instead of cloning again. Work in your own practice copy. The following commands are identical in PowerShell and Bash:

~~~text
cmake --preset simulation
cmake --build --preset simulation
ctest --preset simulation
~~~

Configure finds GHDL and writes build instructions. Build analyses the VHDL files. Test runs the simulated circuit and checks its results. Expected: the cpu.instructions test passes. This is a learner check to perform on your computer, not a claim about a supplied binary. To select a GHDL installation outside PATH, configure with a quoted absolute path:

~~~powershell
cmake --preset simulation "-DGHDL_EXECUTABLE=C:/tools/ghdl/bin/ghdl.exe"
~~~

A simulation predicts the behaviour described by a model. It does not program a physical chip. No hardware board is required for this module.


## Trace the decision

~~~vhdl
when x"5" =>
  if acc = 0 then pc <= unsigned(instruction(3 downto 0));
  else pc <= pc + 1; end if;
~~~

The condition reads the accumulator's current value. The selected assignment takes effect after the process suspends. JZ does not change the accumulator.

## Make a trace table

| Input instruction | Accumulator before edge | Address before edge | Address after edge |
| --- | --- | --- | --- |
| x"58" | 2 | 2 | 3 |
| x"58" | 0 | 4 | 8 |
| x"4F" | 1 | 10 | 15 |

The first instruction does not take the branch because the accumulator is nonzero. The second takes it. The third is unconditional.

## Connect the table to the testbench

1. Find LOAD 3 and SUB 1. The accumulator becomes 2.
2. Find the following JZ 8 assertion. It checks address 3.
3. Find SUB 2. The accumulator becomes zero.
4. Find the next JZ 8. It checks address 8.
5. Run the tests and compare each assertion with the table.

The testbench supplies instructions directly. It does not yet fetch an instruction from a program memory using address. This makes each CPU operation easy to isolate.

## Plan a program memory

A future ROM, or read-only memory, can map each address to an instruction. An address of 0 might return LOAD 3, address 1 SUB 1 and address 2 JZ 4. Connecting that ROM adds a timing assumption: the instruction must be stable before the next CPU clock edge.

Draw address flowing from CPU to ROM and instruction flowing back. Keep this extension separate until you have tested the CPU's operations.

## Check your understanding

Why test both taken and untaken branches? A decoder that always jumps could pass the zero case while still being wrong. The nonzero case checks the other decision.
