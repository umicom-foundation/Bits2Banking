# Read the inputs, outputs and stored state

## What you will learn

A port is a named connection on a circuit. An input receives a value from outside; an output exposes a result. State is information retained between steps. You will separate connections from the internal registers that drive them.

## Set up this exercise

A terminal is a window in which you type commands. A folder holds the files of a project. Install Git, CMake 3.26 or later, Ninja and GHDL with VHDL-2008 support; make their executable folders available on PATH. PATH is the list of folders the terminal searches for programs. Open a fresh PowerShell or Bash terminal and check:

~~~text
git --version
cmake --version
ninja --version
ghdl --version
~~~

Each command should print a version. If a command is not found, correct its installation or PATH before continuing. Download the Bits2Banking repository with Git if you do not already have it:

~~~text
git clone https://github.com/umicom-foundation/Bits2Banking.git
cd Bits2Banking/labs/hardware/vhdl-cpu
~~~

If you already have the repository, open its labs/hardware/vhdl-cpu folder instead of cloning again. Work in your own practice copy. The following commands are identical in PowerShell and Bash:

~~~text
cmake --preset simulation
cmake --build --preset simulation
ctest --preset simulation
~~~

Configure finds GHDL and writes build instructions. Build analyses the VHDL files. Test runs the simulated circuit and checks its results. Expected: the cpu.instructions test passes. This is a learner check to perform on your computer, not a claim about a supplied binary. To select a GHDL installation outside PATH, configure with a quoted absolute path:

~~~powershell
cmake --preset simulation "-DGHDL_EXECUTABLE=C:/tools/ghdl/bin/ghdl.exe"
~~~

A simulation predicts the behaviour described by a model. It does not program a physical chip. No hardware board is required for this module.


## Follow a value through the model

Open rtl/learning_cpu.vhd. The entity declares clock, reset, enable, instruction, address, accumulator, halted and fault. The architecture defines how they behave.

| Name | Direction | Meaning |
| --- | --- | --- |
| clock | Input | A repeated signal whose rising edge triggers a step. |
| reset | Input | Requests a known starting state. |
| enable | Input | Allows one instruction to execute at the next rising edge. |
| instruction | Input | Eight binary digits holding an operation and operand. |
| address | Output | Four-bit index of the next instruction. |
| accumulator | Output | Current eight-bit arithmetic result. |
| halted, fault | Outputs | Report a stopped CPU and an invalid instruction. |

The internal pc signal is the program counter. The internal acc signal is the accumulator. Both use unsigned, a type from ieee.numeric_std that gives binary vectors an unsigned numeric meaning.

~~~vhdl
address <= pc;
accumulator <= acc;
~~~

These are concurrent assignments: their relationships remain active as signals change. They connect internal registers to output ports. The <= symbol schedules a signal update; it is not the C comparison operator.

## Trace a reset

1. In the testbench, find reset initialised to '1'.
2. Find the first call to step.
3. In the CPU process, follow rising_edge(clock), then reset = '1'.
4. Observe the scheduled assignments that clear pc and acc.
5. Locate the assertion that checks the starting values.

The syntax (others => '0') fills every bit with zero. It remains correct if the declared width changes, although the instruction format and tests would also need review.

## Draw the circuit boundary

On paper draw a box labelled CPU. Put clock, reset, enable and instruction on the left. Put the four outputs on the right. Inside the box draw pc and acc registers. This diagram explains the interface before you inspect the operation decoder.

## Troubleshoot

If the compiler cannot find unsigned or resize, check the use ieee.numeric_std.all declaration. If outputs appear unknown before the first reset edge in a modified design, inspect initialisation and reset timing rather than assuming a wire contains zero.

## Check your understanding

Does changing instruction immediately change the accumulator? No. In this model the accumulator changes only at an enabled rising edge, unless reset takes priority.
