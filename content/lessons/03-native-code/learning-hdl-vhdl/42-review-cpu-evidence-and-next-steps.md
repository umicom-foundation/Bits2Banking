# Review CPU evidence and plan the next extension

## What you will learn

A useful project report states what was checked and what remains outside the model. You will assemble evidence from source, tests and waveforms, then choose an extension with a clear acceptance condition.

## Set up this exercise

A terminal is a window in which you type commands. A folder holds the files of a project. Install Git, CMake 3.26 or later, Ninja and GHDL with VHDL-2008 support; make their executable folders available on PATH. PATH is the list of folders the terminal searches for programs. Open a fresh PowerShell or Bash terminal and check:

~~~text
git --version
cmake --version
ninja --version
ghdl --version
~~~

Each command should print a version. If a command is not found, correct its installation or PATH before continuing. Download the Bits2Banking repository with Git if you do not already have it:

~~~text
git clone https://github.com/umicom-foundation/Bits2Banking.git
cd Bits2Banking/labs/hardware/vhdl-cpu
~~~

If you already have the repository, open its labs/hardware/vhdl-cpu folder instead of cloning again. Work in your own practice copy. The following commands are identical in PowerShell and Bash:

~~~text
cmake --preset simulation
cmake --build --preset simulation
ctest --preset simulation
~~~

Configure finds GHDL and writes build instructions. Build analyses the VHDL files. Test runs the simulated circuit and checks its results. Expected: the cpu.instructions test passes. This is a learner check to perform on your computer, not a claim about a supplied binary. To select a GHDL installation outside PATH, configure with a quoted absolute path:

~~~powershell
cmake --preset simulation "-DGHDL_EXECUTABLE=C:/tools/ghdl/bin/ghdl.exe"
~~~

A simulation predicts the behaviour described by a model. It does not program a physical chip. No hardware board is required for this module.


## Capture an identifiable result

Record the repository revision, your local modifications, GHDL version, CMake version and complete test command. A pass belongs to those source files and that environment. Keep failed runs too; they explain why later changes were made.

The supplied checks cover reset, LOAD, ADD, SUB, JUMP, both JZ outcomes, pause, halt, invalid opcode and arithmetic/address wraparound. Inspect the assertions before claiming that an operation was exercised.

## Read a waveform

Run the simulate target. Open cpu.ghw with a compatible waveform viewer. Add clock, reset, enable, instruction, address, accumulator, halted and fault to the view.

1. Locate the first rising edge during reset.
2. Locate LOAD 3.
3. Find the disabled cycle and verify that state stays constant.
4. Find the taken branch to address 8.
5. Find the final invalid instruction and its fault output.

The waveform helps explain a result; assertions remain the repeatable automated checks.

## Choose one extension

A program ROM is a useful next project. Define its address-to-instruction table, connect its output to the CPU, and check that an entire small program reaches an expected result. Other extensions include a store instruction, memory interface, status flags or a wider immediate encoding.

For each extension write the interface, timing rule, failure behaviour and test before changing the circuit. Keep the original instruction tests so a new feature does not erase earlier coverage.

## Connect to Umicom development

Framework's VHDL template gives Studio a reusable project recipe. The document language catalogue recognises .vhd and .vhdl files, and the editor's line-comment catalogue supplies the -- prefix. Those services are separate: recognising a filename does not itself provide a language server or hardware debugger.

Read the related Framework source alongside the generated project to see how a thin application consumes shared capabilities.

## Check your understanding

Does a simulation pass mean this CPU can boot Umicom OS on an FPGA? No. That requires a processor architecture, memory and device interfaces, a toolchain, firmware and board qualification beyond this small model. Use the model to learn instruction execution and build evidence before adding those systems.
