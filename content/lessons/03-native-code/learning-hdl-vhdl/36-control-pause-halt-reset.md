# Control pause, halt and reset

## What you will learn

Control signals determine when a circuit may change state. Pause temporarily prevents a step. Halt stops instruction execution until reset. Reset returns the model to a known state. Their priority must be explicit.

## Set up this exercise

A terminal is a window in which you type commands. A folder holds the files of a project. Install Git, CMake 3.26 or later, Ninja and GHDL with VHDL-2008 support; make their executable folders available on PATH. PATH is the list of folders the terminal searches for programs. Open a fresh PowerShell or Bash terminal and check:

~~~text
git --version
cmake --version
ninja --version
ghdl --version
~~~

Each command should print a version. If a command is not found, correct its installation or PATH before continuing. Download the Bits2Banking repository with Git if you do not already have it:

~~~text
git clone https://github.com/umicom-foundation/Bits2Banking.git
cd Bits2Banking/labs/hardware/vhdl-cpu
~~~

If you already have the repository, open its labs/hardware/vhdl-cpu folder instead of cloning again. Work in your own practice copy. The following commands are identical in PowerShell and Bash:

~~~text
cmake --preset simulation
cmake --build --preset simulation
ctest --preset simulation
~~~

Configure finds GHDL and writes build instructions. Build analyses the VHDL files. Test runs the simulated circuit and checks its results. Expected: the cpu.instructions test passes. This is a learner check to perform on your computer, not a claim about a supplied binary. To select a GHDL installation outside PATH, configure with a quoted absolute path:

~~~powershell
cmake --preset simulation "-DGHDL_EXECUTABLE=C:/tools/ghdl/bin/ghdl.exe"
~~~

A simulation predicts the behaviour described by a model. It does not program a physical chip. No hardware board is required for this module.


## Read the priority order

1. The process waits for a rising clock edge.
2. If reset is '1', it clears the state.
3. Otherwise, if enable is '1' and stopped is '0', it executes an instruction.
4. Otherwise, registers retain their values.

No assignment in a clocked branch means the register keeps its previous value. This is how enable pauses the CPU without losing its work.

## Follow the pause test

The testbench loads 3, disables enable, then presents ADD 15. It checks that the accumulator remains 3 and the address remains 1. Testing both registers prevents a partial pause implementation from going unnoticed.

## Follow the halt test

HALT sets stopped. A subsequent LOAD 9 is ignored, so both accumulator and address retain their earlier values. halted is connected to stopped and lets an outside controller observe that state.

## Check reset priority

Reset clears pc, acc, stopped and invalid even when the CPU has halted. If the reset check were nested inside the enabled-and-running condition, a halted CPU could never reset. Locate the reset branch above that condition.

## Practice

In your practice copy add a test that asserts reset while enable is zero. Predict that reset still clears the state. Leave reset asserted for another edge and predict the same state again. A reset request should be repeatable.

## Troubleshoot

If reset appears ineffective, confirm that a rising edge occurs while reset is high. This model uses synchronous reset: changing reset between clock edges does not immediately update registers.

## Check your understanding

What distinguishes pause from halt? Pause is controlled externally by enable. Halt is retained inside the CPU after a HALT instruction; changing enable alone does not clear it.
