# 9. C: write a native note-saving program

C gives programmers direct control over data representation, memory and interfaces to the operating system. It is the primary language for Umicom Framework and Umicom Kernel, with C23 as the intended language standard. Learning C helps you understand what higher-level runtimes do on your behalf.

We will write a small command-line program that appends one note to a text file, then reads the file back. It uses the C standard library for file operations.

## Create `notes.c`

In a new folder, create `notes.c` with these complete contents:

```c
#include <stdio.h>
#include <string.h>

int main(void)
{
    char note[256];

    printf("Write a note: ");
    if (fgets(note, sizeof note, stdin) == NULL) {
        fprintf(stderr, "Unable to read input.\n");
        return 1;
    }

    note[strcspn(note, "\n")] = '\0';
    if (note[0] == '\0') {
        fprintf(stderr, "A note cannot be empty.\n");
        return 1;
    }

    FILE *output = fopen("notes.txt", "a");
    if (output == NULL) {
        perror("Unable to open notes.txt");
        return 1;
    }

    if (fprintf(output, "%s\n", note) < 0) {
        fprintf(stderr, "Unable to write the note.\n");
        fclose(output);
        return 1;
    }
    if (fclose(output) != 0) {
        perror("Unable to finish saving notes.txt");
        return 1;
    }

    printf("Saved.\n");
    return 0;
}
```

## Compile it

In a PowerShell terminal where GCC is available:

```powershell
gcc -std=c2x -Wall -Wextra -Wpedantic -o notes.exe notes.c
.\notes.exe
```

On Linux, use `-o notes` and run `./notes` instead. If your compiler does not yet fully support C23, the teaching example also uses a conservative subset supported by older standards; the Umicom project itself targets C23 and must be built using its configured toolchain.

Enter `Design the Umicom task window`. The program prints `Saved.` and creates or appends to `notes.txt`. Run it again with a second note and inspect the file.

## Understand each part

`#include` brings in declarations from library **headers**. The `main` function is a common starting point for a hosted C program. `char note[256]` creates a fixed-size array of bytes to hold text. `fgets` reads at most the available buffer capacity, including space for the terminating null byte.

C strings normally end with a zero byte, written `\0` in a character literal. `strcspn(note, "\n")` finds the position of the first newline character or the terminating null byte. Replacing the newline with `\0` prepares the text for saving.

`FILE *output` is a pointer to a file-stream object managed by the C library. `fopen(..., "a")` opens the file in append mode. `fclose` releases the resource, and its return value can report a final write error.

**One limitation:** an input longer than the buffer may be truncated and leave unread bytes in standard input. The program is deliberately small so you can inspect every operation. A production note service must detect oversized input, validate its encoding, handle concurrent writes, and use a durable storage design.

## Separate functions into modules

As programs grow, we place reusable declarations in `.h` header files and implementations in `.c` source files. A public contract should say what a function accepts, what it returns and who owns the memory it touches.

For example, a function that tests a task count can be declared as:

```c
#ifndef UMICOM_LEARNING_TASK_COUNT_H
#define UMICOM_LEARNING_TASK_COUNT_H

int CalculateRemaining(int total, int completed);

#endif
```

The implementation goes in a source file:

```c
#include "task_count.h"

int CalculateRemaining(int total, int completed)
{
    return total - completed;
}
```

This is a simple function, but production code should also specify the valid input range: for example, `0 <= completed <= total`. Callers must not assume the function enforces a rule it does not check.

## Memory ownership matters

C can allocate dynamic memory with functions such as `malloc` and return it using `free`. A useful habit is to ask **who allocates this memory, how long must it live, and who frees it?** A pointer to expired storage can cause a crash or corrupt data. An unchecked array index can read or write outside a valid region. These defects are especially serious in operating systems and financial platforms.

Umicom Framework uses public C interfaces and explicit ownership rules so applications can share services without depending on private implementation details.
