# Keep something you can find again

Explain a file, a folder and a path, and distinguish editing from saving.

**Before you begin:** read [What does a computer do?](02-input-instructions-and-results.md), or use it for a refresher.

## A file holds information

A file is a named collection of information stored by a computer. A text file holds text; a photograph file holds information used to display a picture. A folder groups files and other folders. Folders are also called directories. These names describe ways of organising information, not separate boxes inside the computer.

A filename identifies one item in a folder. In the name greeting.txt, greeting is a descriptive part and .txt is an extension, a usual clue that the file contains plain text. Plain text contains characters without the rich formatting of a word-processing document. A filename is a label, not proof that the contents have a particular format.

## An address for a file

A path describes how to reach an item through folders. Imagine a paper cabinet named Learning, containing a folder named Practice and a page named greeting.txt. We can write the route as Learning / Practice / greeting.txt. Each slash in this paper example separates one step in the route.

On Windows you may see a path such as C:\Learning\Practice\greeting.txt. C: identifies a drive location and the backslashes separate folders. Other systems commonly use forward slashes. You do not need to create that exact path. The example explains notation; your permitted practice folder may be elsewhere. An absolute path starts from a named root location. A relative path starts from a location already chosen.

## Editing, saving and reopening

Editing changes what you are working on. Saving asks the application to store those changes in a file. Opening or reopening asks it to read a file. Some applications save automatically and some require a Save action; learn which behaviour your application uses. A visible sentence on a screen alone does not prove it was saved where you intended.

If you choose Save As, the application usually asks for a name and location. Choosing the same name in the same folder may replace an existing file. A copy is a separate item; changing a copy does not normally change the original. A shortcut is usually a reference to an item, not an independent copy of its contents. These distinctions matter when practising safely.

## An optional device activity

If you have permission, use a basic text editor on your device. A text editor is an application for writing and changing text. Make a new note rather than opening someone else's work. Type a fictional greeting, choose Save As and select a practice folder that you are allowed to use. Choose a new filename, and stop if the application asks to replace a file.

Record the chosen folder and filename on paper. Close only this practice note, reopen the saved item, and check the greeting. Expected result: the text you saved appears. If it does not, inspect the location and name before saving again. You can learn the same idea with labelled paper folders without a device.

## Try it step by step

1. On paper draw Learning containing Practice containing greeting.txt.
2. Write a greeting on a separate page; call that the working copy.
3. Put a copy into the drawn folder and label that action Save.
4. Change the working greeting. Explain which version someone would find by opening the stored copy before you save again.

## Check your understanding

Are two files called greeting.txt necessarily the same file?

**Explanation:** No. Different folders can contain files with the same name. The location is part of identifying the file. Their contents may also differ.
