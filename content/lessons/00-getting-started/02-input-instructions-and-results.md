# What does a computer do?

Separate information going in, instructions being followed, and a result coming out.

**Before you begin:** read [Start with curiosity, not experience](01-learning-at-your-own-pace.md), or use it for a refresher.

## Information travels through a task

Input is information supplied to a system. Processing is the work done on that information according to instructions. Output is the result produced. A system is a collection of parts that work together. Those parts can be very simple: a person, a written rule and three paper cards make a useful practice system.

Suppose a rule says: take two numbers and add them. The inputs are 2 and 3. Processing means adding them. The output is 5. The rule is not the same thing as either input. We can keep the rule and change the inputs to 4 and 1; the output is still 5. We cannot tell which inputs were used merely by looking at that output.

## The parts you can touch

Hardware is physical equipment, such as a screen, keyboard or processor. A processor is a component that carries out machine instructions. Software is the programs and associated information used by the hardware. A keyboard can supply input, and a screen can show output. A touch screen can do both: show a button and detect a touch.

A mouse, touch pad, keyboard, switch or speech-input tool can be different ways of giving an instruction. The idea being learned is the same even if the action you use is different. A computer does not need a screen to work; some computers control equipment or exchange information with other machines.

## A worked example: a greeting

Imagine a program with this rule: show the word Hello followed by the name entered. Entering Mina supplies data. The program combines Hello and Mina and shows Hello Mina. If the input is empty, the programmer must decide what should happen. The machine does not automatically know the person's intention.

An instruction needs a meaning the receiving system understands. Saying something more loudly does not turn an unknown command into a known one. When a program surprises us, we investigate its input, rules and output. We do not assume every unexpected result comes from the person using it.

## Useful limits of the model

Input, processing and output are a starting model: a simplified explanation that helps us ask questions. Real programs may also store information, wait for a reply or repeat work. An output from one program may become an input to another.

For example, a camera produces a picture, a program stores it as a file, and a printer later uses the file to produce a paper picture. Calling the camera only an input device depends on which part of the whole system we are describing. Naming the boundary helps us explain the same event without confusion.

## Try it step by step

1. Draw three boxes labelled Input, Rule and Output.
2. Choose the rule: write the first letter of a word. Try the input cat. The result should be c.
3. Try dog, then an empty input. Decide what the rule should say when no word is supplied.
4. Explain why changing the rule and changing the input are different actions.

## Check your understanding

A screen shows 8. Does that prove the program added 5 and 3?

**Explanation:** No. Many inputs and rules can produce 8. To check the addition example we need to know its rule and the inputs that were actually supplied.

## Before you continue

Continue when you can describe the input, rule and output of one everyday example.
