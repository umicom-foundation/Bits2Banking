# Choose your next learning route

Choose an achievable next step and recognise which knowledge a practical lab expects.

**Before you begin:** read [How applications, an OS and a kernel fit together](07-applications-os-and-kernel.md), or use it for a refresher.

## There is more than one good route

You can explore how a computer works, learn to write programs, study an operating system, or investigate how software helps people in a particular domain. A domain is an area of activity, such as education, music or accounting. You do not need to learn every subject before doing something useful.

A prerequisite is knowledge or equipment that an activity expects you to have first. It is a signpost, not an exclusion. When a lesson lists C arrays as a prerequisite, it should point you to an explanation. An array is an ordered group of values; learning how a C program stores and accesses one takes more work than just knowing that definition.

## From paper instructions to source code

Source code is a program written in a language people can read and edit. A compiler translates source into another form, often machine instructions. A linker connects compiled parts and resolves references between them. Building is the wider process of preparing the program and its necessary files.

The existing C lesson introduces a real note-saving program. Read its explanations of functions, variables and values before trying an OS parser lab. A function is a named piece of a program that performs work; its return value communicates a result to its caller. A parser checks and interprets input according to rules. If those ideas are unfamiliar, keep exploring them before compiling the OS exercises.

## Choose a project small enough to explain

A useful first project might be a private note with an organised filename, a paper algorithm for sorting cards, or a tiny program that prints a greeting. Say what it is supposed to do, what input it receives and how you will check the result. You can extend the project after you understand the first version.

A lab is a practical exercise with source files, instructions and checks. A hosted lab runs as a program under your existing operating system. A native Kernel exercise may require a different compiler and an emulator. Read the prerequisites and expected result before installing anything. Do not mistake a successful small lab for completion of a whole product.

## Keep a record that helps you return

Write a short note containing the lesson title, your last completed activity and one next action. This course does not save completion automatically. A bookmark, a browser feature that remembers a page address, can help you return. A paper bookmark or copied title works too.

When helping another learner, ask them to explain their prediction before offering the answer. When asking for help, describe the task, exact step and observed result. Remove private names or paths before sharing a screenshot. Taking time to understand an error is part of engineering; you do not need to hide it.

## Review before moving on

Try explaining files, memory, instructions, commands and an operating system to someone who has not read the course. If an explanation depends on another unfamiliar word, return to that word's lesson. You can follow the learning map to deeper material and come back here at any time.

The OS and Kernel courses currently provide initial source-reading lessons and hosted labs. They are not complete guides to a production desktop OS. Clear limits help you choose a realistic next activity and understand what a result does and does not demonstrate.

## Try it step by step

1. Choose one route from the linked learning map: computer concepts, first programming, OS services or native Kernel.
2. Write what you already understand and one prerequisite you want to practise.
3. Choose one next lesson rather than installing every tool at once.
4. Make a small learning record with an expected result and room for your observation.

## Check your understanding

What is a useful next step if the Kernel lab mentions C pointers and you have never heard of one?

**Explanation:** Read the introductory C material, then the lesson on pointers and borrowed memory. A pointer represents an address used to access an object; using one correctly also requires learning validity, bounds and lifetime. You can return to the Kernel lab after practising those concepts.

## Before you continue

Choose the route that fits your current understanding. There is no time limit and no requirement to finish every route.
