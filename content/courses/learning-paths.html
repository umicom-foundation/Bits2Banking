Your learning sequence

Follow these stages in order if you are starting without a computing background. Work at your own pace. The question at the end of each stage tells you when to continue; there is no time limit.

Choose a specialist subject

1. Open, save and find your work

Introduction to Computers. No prior knowledge. Follow its eight lessons in order.

Ready to continue when: You can create a folder, recognise a file, and explain input, instructions and output.

2. Read and write a small program

Learning C. Complete First programs, then Working with more information.

Ready to continue when: You can explain values, decisions, loops, functions, arrays, a pointer and the difference between a declaration and a definition.

3. Keep a history of changes

Introduction to Version Control. Use a practice folder after learning to edit and save files.

Ready to continue when: You can describe a local change and a recorded snapshot without discarding work.

4. Build a small Framework application

Umicom Framework Development: first application. Learn the Framework introduction, CMake, SDK use and shared activity rule as one project.

Ready to continue when: You can distinguish configure, build, test and run, and trace one call from its declaration to its result.

5. Give the same program a window

Introduction to GTK4. Continue with the same activity-counter project.

Ready to continue when: You can explain a widget, a signal and a callback, and identify the shared rule used by the window and console.

6. Change a feature and investigate a failure

Build and diagnose the project. Change one rule in your own practice copy; compare expected and observed results.

Ready to continue when: You can reproduce a problem, identify the responsible function and explain the check that should catch it.

7. Extend a shared service

Framework services and application commands. Continue after the first application and diagnostic exercises.

Ready to continue when: You can separate reusable behaviour in Framework from application presentation, then choose one specialist topic.

How to use a lesson

  1. Read its goal and check the ideas it expects you to know.
  2. Read the explanation before copying the example.
  3. Predict what the example will do.
  4. Try one change and compare the result with your prediction.
  5. Explain the result in your own words, then follow Next.

Use Course contents if you lose your place. File numbers are existing chapter identifiers; the displayed course contents gives the study order.

Understand your build tools

Learning Build Systems explains how a source change reaches an executable and a test result. Use its small dependency lab before experimenting with a large application. Learning CMake then explains the project commands in detail.

Programming foundations and guided projects

Start with instructions and values, then choose a focused course. Each course has its own setup summary, ordered lessons, a worked example and recovery guidance. Read the explanations before running commands.

  1. Introduction to Programming — Understand instructions, values, decisions, repetition and functions through small C programs. Start with no programming experience.
  2. Learning Data Structures — Organise values in arrays, stacks and queues, and learn how to keep each structure valid.
  3. Learning Algorithms — Find and order values, trace each operation, and compare the work different algorithms perform.
  4. Learning Pascal — Write, compile and check Pascal console programs using values, decisions, functions and loops.
  5. Safer C Programming — Practise bounds, overlapping memory, explicit ownership, failure preservation and honest safety claims.
  6. Building a Text Editor in C — Build a small console editor from a text buffer through insertion, deletion, undo and saving to a chosen path.
  7. Build a programming-language project — Trace the real Umicom C compiler and inspect its bytecode.

A suggested C route is Introduction to Programming → Learning C → Data Structures → Algorithms → Safer C → Text Editor → Compiler. Pascal is an independent language route. Course chapters state their limits; these introductory sections do not constitute complete coverage of each subject.

One application model, several platforms

Continue after learning C functions and values. Start with the shared model, then choose the interface you want to build. Hardware description is a separate route that begins with bits and signals.

  1. Learning HDL and VHDL
  2. Learning iPhone Development
  3. Introduction to RISC-V
  4. Learning Umicom Framework
  5. Android Development

The mobile and browser labs reuse a bounded C model. They do not establish that the complete Framework SDK runs on those targets. The circuit labs use simulation before any physical-board work.

Build, protect and extend a Framework project

Choose one subject below. Each course starts with its own setup summary. Practical steps use small examples and explain what to inspect when an operation fails.

  • Learning CMake — Understand targets, dependencies, incremental builds and test selection.
  • Learning Cyber Security — Recognise unsafe memory, validate input and protect account boundaries.
  • Learning VHDL — Describe clocked hardware and simulate the small Studio CPU project.
  • Learning Message Queues and RabbitMQ — Trace retries, acknowledgement, duplicate detection and worker ownership.
  • Learning NoSQL — Model documents, query them and understand connector lifetime.
  • Build an LLM from Scratch — Continue with reviewed document datasets, training and evaluation.
  • Learning Umicom Framework — Author and verify an offline learning module for Studio.

Build desktop and web interfaces

Use one Framework C validation contract from two different interfaces. These small laboratories explain ownership, event connections, input boundaries and observable results.

  • Learning Qt — Build and inspect a desktop widget application.
  • Learning Wt — Build a local web application with separate session state.
