Pause before a reached source line

A debugger can pause a program at a place you want to inspect. The temporary until command in the Umicom C source interpreter pauses before the next reached statement that begins on the requested line. A line can be present in the file and still be skipped by a branch.

Practice with two runs

  1. Save the program below as pause.c with its first line at line 1. Use an Umicom C build that supports until.
  2. In a terminal run umicom-c interpret pause.c --step. The prompt identifies the next statement. Type until 6 and press Enter. Expect output for the initial value and the condition, then a prompt at line 6 before total += 34; executes. Line 4 is inside a branch whose condition is false.
  3. Type next to execute line 6, then next again to return. Expect Result: 42. Rerun and type until 4. Execution reaches its normal result and reports that it never reached line 4.
  4. Start again and type until 6, then quit at the pause. Check that the completed statements remain in the trace and there is no Result: line.
int main(void) {
    int total = 8;
    if (0) {
        total += 99;
    }
    total += 34;
    return total;
}

Explain the checks

A line target controls where the console prompts. It leaves the interpreter’s instruction limit in force. Try the same session with --max-steps 1. The budget stops the run before it reaches line 6. An invalid number such as until 6junk leaves the current prompt in place.

Trace rows and the returned value are on standard output. Prompts and reports about an unreached line are diagnostic messages. An editor can display the upcoming source line and keep the execution result separate. Move line 6 across two lines and predict where until will stop. It matches the line on which the statement begins.

Separate program text from interactive commands

Repeat the same program in PowerShell with standard input supplying its text. This run streams the trace and prints Result: 42 after the input closes.

Get-Content -LiteralPath pause.c -Raw | umicom-c interpret --stdin

Using --stdin and --step together makes both the program and the prompt ask for the same stream. The CLI refuses that combination before reading the program. Draw a diagram with the program file, command input and trace output as separate arrows, then show which arrow changes in the piped version.

If the program cannot find the command, check that your executable came from the current Umicom C source build. Then recheck file line numbers and confirm that you started with --step. Umicom C interpreter guide
