Count reached source statements

A source statement is an instruction a programmer writes, such as setting a variable or returning a value. A statement can span several lines. One line can also contain two statements. The Umicom C pause console counts statements that execution reaches.

Predict where the next pause will be

Save the following complete program as practice.c in a fresh exercise folder. Count the source lines starting at one.

int main(void) {
  int x =
    6; x *= 7;
  return x;
}

The declaration starts on line 2 and finishes on line 3 after 6;. The multiplication starts later on line 3. The return is the third reached statement. On paper, write down the value of x after the first statement and after the second.

START with the first reached statement ready
REPEAT up to 2 times
    RUN one reached statement
    REPORT its source location and outcome
    STOP if the program returns or reports an error
PAUSE before the next reached statement

Use the same pause controls on one or several statements

  1. Open PowerShell in the practice folder. Start the current Umicom C tool with umicom-c interpret practice.c --step. The first prompt should start with Next 2:3. The two numbers identify the source line and column.
  2. Type next 2 and press Enter. The tool reports the declaration and multiplication. The new prompt should start with Next 4:3. There is no prompt between the two reported statements.
  3. Type show to preview the pending return. Type next to execute it and expect Result: 42. Starting again and choosing quit at the same pause leaves the return unexecuted.

Use a positive decimal after next. If next 0 or next -2 is refused, the console leaves the current statement pending. Try next 99 at the first prompt. The program returns after its three statements, so the console finishes after printing the result.

The same command works with the pseudocode profile. The instruction allowance, which counts the smaller operations used to run the source, still applies to every request. Use until LINE when you know the exact source line you want to reach. Use --jsonl if another tool reads the events. The same step records go to standard output and the prompts stay on the diagnostic stream.

Studio can use counted steps to let a learner move through predictable parts of a program. It can still display each reached statement and show the pending location after the batch.
