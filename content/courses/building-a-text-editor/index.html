Building a Text Editor in C

About this course

Build a small console editor from a text buffer through insertion, deletion, undo and saving to a chosen path.

Before you begin

You should recognise C variables and functions. The project introduces arrays, byte positions and file operations as they are needed.

Reading order

  1. Plan a small editor with a testable model
  2. Insert and erase text without losing the tail
  3. Undo and save to a chosen path
  4. Test the model and the whole editing session
  5. Open an existing document without losing work
  6. Load into a private candidate before replacing state
  7. Recognise line endings and end of file
  8. Check failure state and command results
  9. Own a shared text buffer and respect borrowed views
  10. Resolve exact UTF-8 offsets and UTF-16 positions
  11. Select source words and physical lines without changing text
  12. Capture an edit for the intended document
  13. Traverse shared undo history and create a new edit branch
  14. Check refused edits, preserved state and SDK identity

Continue with shared Framework services

Lessons 1–8 retain the standalone ASCII editor. Lessons 9–14 use an installed Framework SDK to teach text ownership, exact Unicode positions, source selection, captured document edits and bounded Undo/Redo. The new console lab contains twelve in-memory scenarios and does not create a native window.

Prepare a development environment

A compiler translates C source. CMake describes which files belong to a program. Ninja performs the build work. CTest runs registered checks. An editor changes the source text. You may use a plain text editor before learning an IDE.

Windows with PowerShell

  1. Install MSYS2 from its official installation guide. Use the UCRT64 environment described in the environment guide.
  2. In the MSYS2 UCRT64 terminal, follow its update instructions, then install the C tools:
pacman -S --needed mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-cmake mingw-w64-ucrt-x86_64-ninja git
  1. Obtain the Bits2Banking repository. If it is already present, use that checkout; do not clone into it again. In the MSYS2 terminal, an example new location is:
mkdir -p /c/umicom
git clone https://github.com/umicom-foundation/Bits2Banking.git /c/umicom/Umicom-Bits2Banking
  1. Open PowerShell and add the tools to that terminal's PATH. PATH is the list of directories searched for commands.
Set-Location "C:\umicom\Umicom-Bits2Banking"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
gcc --version
cmake --version
ninja --version
  1. Read the files under labs/native/text-editor. Run one command at a time and stop on an error. Check $LASTEXITCODE immediately after a native command; zero reports success.
cmake -S labs/native/text-editor -B build/text-editor -G Ninja -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build/text-editor --parallel 2
ctest --test-dir build/text-editor --output-on-failure --no-tests=error
& ".\build\text-editor\btb-text-editor.exe"

Linux with Bash

  1. Install Git, a C compiler with the required C23 mode, CMake 3.24 or newer, and Ninja using your distribution's documented package manager. Package names and compiler versions vary.
  2. Clone into a new folder if needed:
mkdir -p "$HOME/umicom"
cd "$HOME/umicom"
git clone https://github.com/umicom-foundation/Bits2Banking.git Umicom-Bits2Banking
cd Umicom-Bits2Banking
  1. Check cc --version, cmake --version and ninja --version. If you choose a different compiler, configure a new build directory with -DCMAKE_C_COMPILER set to that compiler.
  2. Run each command separately and stop on a failure. echo $? immediately afterwards displays the previous result.
cmake -S labs/native/text-editor -B build/text-editor -G Ninja -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build/text-editor --parallel 2
ctest --test-dir build/text-editor --output-on-failure --no-tests=error
./build/text-editor/btb-text-editor

Understand the result

The editor prints its command summary and waits for input. Type append Hello, then show, then discard on separate lines. Expect TEXT: Hello. This is a bounded ASCII console lab with one-level undo, not a graphical production editor. The -S argument selects source; -B selects a separate build directory. Building again in that same directory normally updates changed inputs and their dependencies. Testing is a separate step. A successful compile does not establish that the tests or a user workflow passed.

If setup fails

A missing command means its tool is not installed or not on PATH. A compiler-mode error means you need a compiler that supports the requested C mode. A missing build.ninja file means configuration did not finish successfully. Read the first diagnostic before repeating later commands. Keep source separate from generated build files.

For a slower explanation, use Learning C. The CMake command manual explains configuration and build options.

What to practise next

Use Safer C Programming to review the buffer and file-operation boundaries. Then return to chapter 3 to trace the Framework document APIs before planning a graphical editor. The compiler course offers a separate language project when you are ready to study parsing.

Scope

These are introductory chapters and practical labs. Further topics remain to be developed. Successful reading or compilation alone does not establish runtime correctness; compare expected results with your own checks.
