Check a C and Java translation

A local variable belongs to one function or method. In this lab, a translator preserves where two integer locals are initialized, when one is reassigned and how the final value is returned. The sample uses fixed practice values.

Setup recap

Open a new writable directory. Put a build of umicom-c with the checked function translator, a C23 compiler with a 32-bit int, and a JDK on your command path. Confirm that umicom-c --version, gcc --version and javac -version run before creating the fixture.

1. Translate the function in both directions

Save this file as answer.c. Predict the value of net immediately before the return.

int answer(void) {
    int net = 6;
    int fee = 3;
    net = (net + fee) * 5;
    return net - fee;
}
umicom-c translate c-to-java answer.c UmicomAnswer.java
umicom-c translate java-to-c UmicomAnswer.java answer-roundtrip.c

Open both generated files. Check the initializers, reassignment and return order. The reassignment makes net equal to 45, so the returned value should be 42. If an output already exists, choose a fresh filename or work directory.

2. Build and run both results

Save this Java entry point as Fixture.java.

final class Fixture {
    public static void main(String[] args) {
        System.out.println(UmicomAnswer.answer());
    }
}
javac UmicomAnswer.java Fixture.java
java -cp . Fixture

Save this C entry point as fixture.c.

#include <stdio.h>
int answer(void);
int main(void) {
    printf("%d\n", answer());
    return 0;
}
gcc -std=c23 -Wall -Wextra -Werror fixture.c answer-roundtrip.c -o c-check.exe
.\c-check.exe

On Linux, use ./c-check.exe to run the same output filename. Each program should write 42 on one line. Compare the two results with the value you predicted.

3. Check the boundary

In a new source copy, initialize net to 2147483647 and reassign it with net = net + 1;. Run the translation with an unused destination. Expect a diagnostic and no destination file. This arithmetic lies outside the shared signed 32-bit range. Keep this as a translation refusal exercise.

The profile supports decimal integer expressions, initialized locals, simple assignments and a final return. Java objects, parameters, loops and general project conversion need additional implementation. Try another pair of small values and repeat both compilation checks.

4. Check the installed translator from C

The earlier steps call the command-line tool. A C application can call the same translator through the Umicom C SDK. A CMake component names what the code needs. The imported target supplies the installed headers and libraries needed to link the application.

From an Umicom C source directory already built into build, use PowerShell to stage the SDK and build the independent example.

cmake --install .\build --prefix .\installed-sdk
$translationPackage = (Resolve-Path -LiteralPath .\installed-sdk\lib\cmake\UmicomC).Path
cmake -S .\examples\translate_sdk_consumer -B .\build-translation-consumer "-DUmicomC_DIR=$translationPackage"
cmake --build .\build-translation-consumer
ctest --test-dir .\build-translation-consumer --output-on-failure

Expect umicom.c.installed_translation_consumer to pass. Open the example's main.c, find the two translation calls, and explain where the second call gets its source length. The test checks the restored C text. Steps 1 and 2 give you the separate Java and C program results.

If CMake refuses the Translation component before building the example, find the UmicomCConfig.cmake file from your installed SDK and check the directory you passed. Umicom C SDK guide
