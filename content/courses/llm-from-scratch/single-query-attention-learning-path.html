Course sequence

  1. Define the single-query attention contract · Specify the boundary of an attention operator that computes the newest query only, without changing the established Transformer model.
  2. Trace head-local key and value layout · Calculate flat memory offsets safely and recognise when tensor layout differs from logical attention shape.
  3. Calculate one-query causal attention · Compute scaled dot products, softmax probabilities and the weighted value vector by hand.
  4. Preserve causal masks and padding semantics · Ensure the single-row optimisation gives attention only to valid past and current tokens.
  5. Budget single-query scratch memory · Compare score-buffer and streaming-normaliser designs without assuming reduced memory is automatically faster.
  6. Compare the last canonical attention row · Choose a non-circular numerical oracle for the new operator.
  7. Keep learned position embeddings consistent · Explain why shifting a bounded context invalidates cached representations.
  8. Preserve head concatenation and output projection · Track the shape and ordering of the attention result before the residual connection.
  9. Qualify layer-by-layer and vocabulary-logit parity · Escalate from a correct attention row to a correct multi-layer prediction.
  10. Validate cache identity, shape and lifetime · Separate cache correctness from memory safety and checkpoint trust.
  11. Keep single-query proposals failure-atomic · Design rejection and cancellation boundaries that never leave half-published inference state.
  12. Treat context rollover as a slow-path gate · Build an unambiguous routing policy for unchanged-position appends versus full-window rebuilds.
  13. Design adversarial single-query fixtures · Create small, diagnostic cases that expose masking, layout, arithmetic and lifetime faults.
  14. Benchmark one-query attention with fair controls · Plan Release comparisons that separate kernel work from whole-session latency.
  15. Plan portable CPU kernel optimisation · Separate a correct portable C23 reference from later hardware-specific acceleration.
  16. Define the single-query kernel acceptance gate · Turn lessons 233–247 into a concrete, reviewable plan for the next Framework engineering batch.

Before interpreting results

A dedicated single-query kernel is the next engineering target, not a completed production feature. Framework numerical parity, lifetime tests and Release timings must be verified before any acceleration claim.
