LESSON 84 · NATIVE C23 · TRAINING PREPARATION

Qualify Batched Rotary Forward and Backward Operations

Move from one Q/K vector to bounded multi-head gradients with independent evidence.

Learning objectives

Qualify forward and backward RoPE calculations for multi-head batches, map each time step to the correct absolute token index, test memory ownership and failure-atomic output behaviour, and establish the precise remaining work before Umicom can claim to have a trainable rotary language model.

1. Move from one vector to a real training tensor shape

In Lesson 83, a projected query or key contained one head-sized vector. Transformer training processes batches and multiple attention heads. A practical C23 training interface therefore needs a well-defined row-major layout. The new UmiAiTrainingRotaryTensorForward and UmiAiTrainingRotaryTensorBackward APIs operate on a bounded tensor with logical shape [batchCount, sequenceLength, attentionHeads, headChannels]. The flattened storage has tokenRows = batchCount × sequenceLength rows and attentionHeads × headChannels columns.

For example, with two independent sequences, six time steps, two heads and four channels per head, the buffer contains 2 × 6 × 2 × 4 = 96 float32 elements. One sequence might start at absolute position 0 and the other at 3071. The same trained projection weights can apply to each sequence, but the RoPE angle depends on that sequence's starting position and current time step.

2. Absolute positions are not array indices

A row index chooses a location in the in-memory tensor. An absolute position chooses an angle in the rotary embedding. They must not be conflated. For each row r, the current batch index is r / sequenceLength and its local time is r % sequenceLength. The position is startPositions[batchIndex] + localTime. The implementation validates that none of those sums exceeds the established RoPE limit.

If no start-position array is supplied, all sequences begin at position zero. If one is supplied, it must contain exactly one entry for each batch sequence. This explicit rule prevents accidental sharing of position state between independent documents or customer conversations.

3. Reuse one mathematical owner for forward and reverse mode

Both batch functions dispatch to the Framework's existing per-vector rotary service. The forward function calls UmiAiTrainingRotaryRotate for each row and attention head. The backward function calls UmiAiTrainingRotaryRotateAdjoint. The batch module does not implement a second cosine/sine engine; nor does it train or own any decoder parameters.

#include "umicom/ai/training/rotary_training.h"
#include <stdint.h>

int main(void)
{
    const UmiAiTrainingRotaryConfig cfg = {4U, 4U, 10000.0};
    const uint64_t firstPositions[2] = {0U, UINT64_C(3071)};
    float queries[96] = {0};       /* [2, 6, 2, 4] */
    float rotated[96] = {0};
    float upstream[96] = {0};
    float inputGradient[96] = {0};

    /* Normally queries come from a Framework training-tape projection,
     * and upstream comes from that same tape's attention backward pass. */
    for (size_t i = 0U; i < 96U; ++i) {
        queries[i] = (float)(i % 11U) * 0.03F;
        upstream[i] = (float)(i % 7U) * 0.02F;
    }
    if (UmiAiTrainingRotaryTensorForward(&cfg, queries, 12U,
            6U, 2U, firstPositions, 2U, rotated, 96U) != UMI_STATUS_OK)
        return 1;
    if (UmiAiTrainingRotaryTensorBackward(&cfg, upstream, 12U,
            6U, 2U, firstPositions, 2U, inputGradient, 96U) != UMI_STATUS_OK)
        return 2;
    return 0;
}

Every tensor dimension is an element count. The complete candidate output is staged before publication, so in-place calls are permitted and numerical errors do not expose half-written results. The bounded implementation handles no more than 16,384 float elements and 32 channels per row. Those limits belong to this educational laboratory, not a future production-scale LLM.

4. Use an independent adjoint identity

There is an especially useful numerical test for any linear transformation R. For arbitrary vectors x and g, dot(Rx, g) = dot(x, Rᵀg). The left side uses the full forward batch output; the right side uses the backward output. Their difference should be very small for finite float32 values. This catches transpose errors even when no trainable model exists yet.

The delivered rotary_tensor regression tests that identity with two distinct sequence offsets, two attention heads, in-place operations and explicit checks against individual scalar RoPE calls. The rotary_gradients regression additionally checks 56 combinations of configuration and query/key position, perturbing every relevant input component independently. The rotary_training_rejections regression verifies unchanged outputs after invalid positions, nonfinite values, overlapping result ranges and insufficient capacities.

The delivered regressions use the actual rotary source, not substituted rotation or derivative implementations. An isolated GCC/Clang validation cannot, by itself, establish that the complete production decoder, training tape and Windows application tree compile together. The project must still run the full lab and consolidated build in the approved Windows development environment.

6. What remains before a trained RoPE decoder

These results qualify a building block, not an end-to-end model. A separately identified trainable RoPE decoder still requires a tape-owned rotary operator with reverse-mode graph integration; full attention and feed-forward differentiation; a decoder configuration that deliberately omits learned absolute-position embedding weights; model-family-specific checkpoint encoding/decoding; training and evaluation parity; and inference/cache equivalence across the intended context policy.

Equally importantly, RoPE does not guarantee that the upper layers of a multi-layer transformer can reuse retained hidden states after old tokens are evicted. Exact full-window equivalence can require recomputation of hidden representations in those layers. Position-correct caches and semantically equivalent attention states are different engineering claims and must be tested separately.

7. Practical exercises

  1. For three sequences of eight tokens and four heads of four channels each, calculate the total projected tensor element count.
  2. In the second sequence with startPositions[1]=120, what absolute position is assigned to its seventh token?
  3. Explain why dot(Rx,g)=dot(x,Rᵀg) is a stronger test than only checking that an output has finite values.
  4. What happens if a 96-element caller buffer advertises capacity 95? Which memory may change?
  5. List the additional graph, checkpoint and multi-layer experiments needed before using this operator to train an AI assistant for Umicom Studio IDE.

Key lesson: a reliable trainable model is assembled from individually qualified forward and backward operators under explicit tensor, position, lifetime and checkpoint contracts.
