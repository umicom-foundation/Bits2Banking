LESSON 91 · UMICOM FRAMEWORK · C23

Qualify the Real Rotary Training Tape

Verify gradient mathematics against the actual Framework tape, with every formula explained in ordinary language.

For readers from any background: The mathematical operations are explained with ordinary numbers before the code is introduced. You can pause at the Mathematics for AI companion and return to this exact lesson afterwards.

1. Why our next engineering step is verification, not another model

Earlier lessons introduced rotary position mathematics, a differentiable rotary-attention path and a small query/key training experiment. The next challenge is not writing another attention formula. It is establishing that the implementation works with the real Umicom Framework training tape, including its memory owner, lifetime rules, automatic differentiation and rollback behaviour.

The Framework source remains the authority. The new tests link to the existing Umicom::AiTraining target, not a copied tape or a different numerical implementation. The original learned-absolute-position decoder and its checkpoint files are unchanged.

2. Read the tensor dimensions before the mathematics

Imagine three customer-service enquiries in Umicom Desk. A small experimental model represents each one by four numerical features. That gives a table with 3 rows × 4 columns, or twelve numbers. For training, we use separate query and key tables with the same shape.

shape = [3, 4]   →   3 × 4 = 12 elements

3 counts token rows; 4 counts channels (features) per row. Two attention heads each receive two channels because 4/2=2. These are experimental numerical features, not bank-account amounts or personal customer data.

Need to practise shapes first? Maths Unit 16 explains tables, flat indexing and attention heads from the beginning.

3. What a gradient means, using one weight

Suppose we have a weight w=1, a prediction p=2w+1 and a target value of 5. The prediction is 3. Define the loss as half the squared error: L=(p−5)²/2=2. A derivative tells us how the loss changes after a small weight adjustment. At w=1, the derivative is −4.

dL/dw = (dL/dp) × (dp/dw) = (−2) × 2 = −4

L is the loss, p the prediction and w the weight. The symbol d introduces a rate of change. The negative sign tells us a small increase in this weight will initially reduce the loss.

See Maths Unit 17 for every arithmetic step before returning to the Framework's multi-head query/key gradients.

4. Independently check a Framework gradient

The training tape calculates gradients by working backwards through the recorded operations. A second approach estimates the change numerically by evaluating the loss at two nearby values. It does not rely on the tape's backward logic.

estimated gradient ≈ [L(w+h) − L(w−h)] / [(w+h) − (w−h)]

L is loss; w is one input component; h is a small positive test change (in this test, 0.002). The numerator is the change in measured loss. The denominator is the actual separation between the two represented FP32 input values.

For the simple L=(p−5)²/2 example above, if w changes from 1 to 1.1, the loss drops from 2 to 1.62. A central-difference test is more accurate than this one-sided illustration because it measures on both sides of the same starting value.

The new rotary_real_tape_gradients regression performs 72 comparisons: twelve query and twelve key components, each checked at three different starting positions. Its specific absolute tolerance is 0.0020; this is not a universal rule for neural-network mathematics.

5. Trace the code without becoming lost in C syntax

/* Simplified sequence of REAL Umicom Framework API calls. */
UmiAiTrainingTape *tape = NULL;
UmiStatus status = UmiAiTrainingTapeCreate(&tape);
/* Create query, key, value and target tensors on the tape. */
/* Compose rotary attention and MSE; reject any failed step. */
status = UmiAiTrainingBackward(tape, loss);
if (status == UMI_STATUS_OK) {
    status = UmiAiTrainingTensorGradients(query,
                                         queryGradient, 12U);
}
/* Destroy the tape once after releasing all work owned by it. */
UmiAiTrainingTapeDestroy(tape);

The & character gives C access to a variable whose value a function must fill. The Framework remains the sole owner of the tape's internal memory. The small excerpt shows the intended order; the full test contains error checks, fresh tape creation for each comparison and a complete cleanup path.

6. A useful distinction: two independent things to verify

CheckQuestion it answersQuestion it does not answer
Analytic vs numerical gradientsDoes this tape's backward path agree with changes in its forward loss?Is its forward attention formula independent of other mistakes?
Earlier independent loss oracle (Lesson 89)Does the forward loss agree with an independently written mathematical reference?Will a very large future LLM be correct or fast?
Memory and rollback tests (Lesson 92)Does a failed graph operation preserve published state and release tracked nodes?Can no other memory defect ever occur?

These three checks support one another; none replaces all the others.

7. Practical exercise with answers

  1. How many numerical values are in three rows with four channels each?
  2. Why do we change only one query or key value at a time when estimating its gradient?
  3. If the numerical estimate is 0.0030 and the tape gives 0.0034, what is the absolute difference? Does it meet a 0.0020 threshold?
Reveal the worked solutions

1. 3×4=12 values. 2. Changing one value isolates its local effect on the loss, making the derivative meaningful. 3. |0.0034−0.0030|=0.0004. Since 0.0004≤0.0020, it passes this test's stated absolute threshold.

8. Build and run the production-linked regression

Set-Location 'C:\umicom\Umicom-Applications'
$env:Path = 'C:\msys64\ucrt64\bin;' + $env:Path
cmake -S '.\framework\learning\native-llm\prefix-work' `
  -B '.\build\windows-ucrt64-native-llm-prefix-debug' `
  -G Ninja -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
if ($LASTEXITCODE -ne 0) { throw 'Configure failed.' }
cmake --build '.\build\windows-ucrt64-native-llm-prefix-debug' `
  --target umicom-ai-training-rotary-real-tape-gradients-test --parallel 2
if ($LASTEXITCODE -ne 0) { throw 'Build failed.' }
ctest --test-dir '.\build\windows-ucrt64-native-llm-prefix-debug' `
  -R '^framework\.ai\.training\.rotary_real_tape_gradients$' `
  --output-on-failure --no-tests=error
if ($LASTEXITCODE -ne 0) { throw 'Real-tape gradient test failed.' }

Do not describe production Windows integration as passing until this command actually succeeds on the target machine. The current exercise is a bounded component test, not a completed rotary decoder.
