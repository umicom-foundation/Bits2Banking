LLM from Scratch — Lesson 433: Map authenticated peers to authorised training assignments

Bits to Banking · Umicom Foundation
Author: Sammy Hegab
Language: UK English · Native implementation: C23/Assembly where technically justified

Learning outcome

Describe why a correct MAC is necessary but insufficient for permissioned training.

Concept and mechanism

A symmetric MAC says that some entity possesses the secret. If one secret is shared across all contributors, the verifier cannot confidently distinguish which participant emitted a message. A permissioned design binds each high-entropy key to a worker registry entry, role, expiry and approved dataset scope. The coordinator then checks the existing FederatedJob admission, checkpoint and policy commitments.

Guided reasoning

  1. Authenticate the transport and key epoch.
  2. Consult the Framework identity registry.
  3. Apply deny-by-default authorisation for the dataset shard.
  4. Verify the frame’s contributor ID matches the enrolled key.
  5. Match the round and public sequence to a private in-process ticket.

Worked example

Worker A owns key KA and is assigned shard SA. A tag generated by KA over a result that claims worker B or shard SB must still be refused by the identity/policy layer even though the MAC is valid for KA.

How this connects to a native software system

The authoritative AI, identity, messaging, cryptographic and numeric contracts belong in Umicom Framework. Applications such as Umicom LLM, Studio, RAG and Education consume those capabilities through established APIs, rather than implementing independent maths, secret stores or message parsers. Where a specialised feature is not present, it is an explicitly scoped research or future-development topic—not a claim that all components exist today.

Correctness and research boundary

Do not infer that a SHA-256 hash authorises access to a confidential document; rights are an independent recorded decision.

Test your understanding

Question: Can a valid HMAC under a group-wide secret establish which of five workers trained a submitted update?

Reveal the worked answer

No. The MAC shows possession of the shared secret, not which worker held it. Per-worker keys and an independently checked sender-to-key registry are needed.
