1. Why not optimise immediately?

In banking software, a faster ledger posting routine is not an improvement if it posts incorrect balances. In an LLM, a faster attention operator is not useful if it produces wrong gradients. First prove correctness using the full Framework training tape. Then measure allocations and speed honestly.

2. What does fusion mean?

Imagine a manufacturing line that passes an object through three separate machines, storing an intermediate result between each. Fusion attempts to combine stages and reduce temporary storage. For RoPE attention, a future Framework-owned tape node might combine Q/K rotation and masked attention. This batch does NOT implement or benchmark that fused node.

3. Which gradients must still work?

input gradient = R(position)ᵀ × output gradient

R(position) is a rotation of two coordinates determined by a token's position. The superscript ᵀ means transpose; for a rotation it reverses the rotation. The multiplication sign means to apply that transformation to the gradient arriving from later layers. If a forward rotation changes [1,0] to [0,1] at a 90° angle, its backward counterpart converts [0,1] to [1,0].

For first-principles explanation, study Maths Unit 7 and Unit 20.

4. Safety rules

The future node must respect two properties: (a) fail without publishing partial tensors and (b) restore the exact live-node count and current tracked bytes after rollback. Historic peak allocation is not expected to decrease. Once the new node is compared numerically against the existing implementation, benchmark under identical model, prompt, hardware and build modes.

5. Practical example

Suppose old attention uses a temporary 600-byte allocation and a proposed operator uses only 400 bytes for the same work. The absolute saving is 600 − 400 = 200 bytes; the percentage reduction is 200 ÷ 600 × 100 ≈ 33.3%. This is only a worked mathematical example—not a measurement from Umicom.

Exercise answer

A saving in allocated bytes alone does not prove the program is faster. Measure CPU time, wall time, accuracy, and correctness separately.
