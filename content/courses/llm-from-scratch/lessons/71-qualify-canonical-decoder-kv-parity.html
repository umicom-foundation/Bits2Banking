LESSON 71 · NATIVE C23 · NUMERICAL QUALIFICATION

Qualify KV Reuse Against the Canonical Decoder

Compare the original decoder mathematics directly with cached inference, not just two schedules of the same cache kernel.

Learning objectives

Distinguish two kinds of evidence: agreement between two execution schedules of the same KV kernel, and independent agreement with the original full-context decoder. Trace a sequence of tokens through learned positions, compare every vocabulary logit, and confirm that no parameter or checkpoint state changes during inference.

1. The missing independent reference

Lessons 69 and 70 established that a growing prefix can be evaluated by repeatedly rebuilding prefixes or by appending a single new row to a persistent KV cache. Those two paths produced the same results, and the incremental path computed fewer token rows. There was one important limitation: both calculations used the same KV-cache implementation. If that implementation made the same numerical mistake in both paths, their mutual agreement would not reveal it.

For this lesson, our independent reference is the Framework's original UmiAiTrainingDecoderLogits function. It executes the authoritative decoder using its training-tape mathematics. The candidate is the existing cache using UmiAiTrainingKvCachePrefill followed by UmiAiTrainingKvCacheAppend. No second tokeniser, attention implementation, learned-position rule or model format is introduced.

Why not compare only the predicted word or token? Suppose two implementations select token ID 42, but one returns logits [4.1, 2.9, ...] and the other [4.1, 0.2, ...]. Their choices happen to agree, but their probability distributions differ. Correct engineering compares the numerical outputs that determine behaviour, not just the final label.

2. One sequence, two independent calculations

Begin with the eight-token context A B C D E F G H. The cache starts with token A at position 0. Each append introduces one new token at positions 1, 2, and so on, without changing the position of a token already present. The cache therefore needs eight computed token rows to reach a full context. At this point, the canonical decoder computes the same eight-token context independently and provides the reference logits for position 7.

OperationKV cache stateCanonical reference
Build the contextPrefill A, then append B through HAll tokens A through H in one decoder logits call
Observe the final rowCached logits from position 7Canonical logits from position 7
ValidateEight computed rows, no rolloverEvery vocabulary logit finite and within tolerance

The comparison uses an absolute tolerance of 0.00004. This value is not an arbitrary promise that every floating-point backend will agree bit-for-bit; it is the existing tolerance used in Umicom's KV-context regression. The qualification rejects non-finite values and any difference above the accepted bound.

3. The Framework API in C23

The public interface is kept small so that Umicom Studio, the AI research tools and later inference hosts can request the same evidence without knowing the cache's private structure:

#include "umicom/ai/training/kv_position_qualification.h"
#include <inttypes.h>
#include <stdio.h>

/* A real decoder was created by the caller. Its contextLength is 8. */
size_t contextIds[8] = {109U, 114U, 120U, 36U,
                        112U, 118U, 121U, 45U};
UmiAiTrainingKvPositionQualification evidence = {0};
UmiStatus status = UmiAiTrainingKvPositionQualify(
    decoder, contextIds, 8U, 37U, &evidence);
if (status == UMI_STATUS_OK) {
    printf("Compared logits: %zu\n", evidence.comparedLogits);
    printf("Rows before eviction: %" PRIu64 "\n",
           evidence.computedRowsBeforeRollover);
    printf("Maximum difference: %.8f\n",
           (double)evidence.maximumAbsoluteDifferenceBeforeRollover);
}

The call uses an exactly full context because the canonical decoder expects a complete sequence of length contextLength. It tests the growing-prefix state at the point where both the incremental and canonical algorithms represent precisely the same token positions. The final argument, token ID 37, is the token that will force the first context rollover in Lesson 72.

Read the structure fields rather than guessing from success alone. contextTokens identifies the context size, vocabularySize identifies how many logits are compared in each full-context state, cacheHeapBytes describes the single cache reservation, and the counters record actual KV work. The total comparedLogits is twice the vocabulary size because this service also checks the first rollover state.

4. A robust qualification is failure-atomic

A certificate of parity must never be published after only half of its checks succeed. The service first validates the model, token count and vocabulary bounds. It allocates a temporary cache, performs both comparisons, inspects the completed optimiser step count and configuration, then publishes the staged result only after all checks pass. Any failure leaves the caller's report unchanged.

The qualification is read-only. It does not modify parameters, write checkpoints or change training history. The dedicated regression test goes further by encoding a checkpoint before and after qualification and comparing the bytes. A match proves that the tested inference call has not altered this checkpoint representation; it does not mean a future positional-encoding variant could reuse the same checkpoint without migration.

5. Build the real decoder comparison

Set-Location 'C:\umicom\Umicom-Applications'
$env:Path = 'C:\msys64\ucrt64\bin;' + $env:Path

cmake -S .\framework\learning\native-llm\prefix-work `
  -B .\build\windows-ucrt64-native-llm-prefix-debug -G Ninja `
  -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
if ($LASTEXITCODE -ne 0) { throw 'Configure failed.' }

cmake --build .\build\windows-ucrt64-native-llm-prefix-debug `
  --target umicom-ai-training-kv-position-qualification-test `
           umicom-ai-training-kv-position-rejections-test `
           umicom-native-llm-position-qualification --parallel 2
if ($LASTEXITCODE -ne 0) { throw 'Build failed.' }

ctest --test-dir .\build\windows-ucrt64-native-llm-prefix-debug `
  -R '^framework\.ai\.training\.kv_position_' `
  --output-on-failure --no-tests=error
if ($LASTEXITCODE -ne 0) { throw 'Regression failed.' }

These commands compile the original decoder and its original KV cache through the existing Framework CMake composition. The new target only orchestrates their calls. The three expected tests are kv_position_qualification, kv_position_rejections and kv_position_demo. A successful result on a specific machine should be recorded with its compiler and revision; a prepared package alone does not prove that machine has run the tests.

Review and exercises

  1. Why could two KV-cache execution schedules agree yet both disagree with the original decoder?
  2. Explain what a logit is and why comparing the highest token ID alone is inadequate.
  3. With vocabulary size 260, how many logits does the two-state service compare?
  4. What information is preserved if an invalid token ID is supplied?
  5. Which regression evidence demonstrates that a call is not updating model checkpoint bytes?

Engineering conclusion: Prefix reuse is a legitimate reduction in token-row computation only when model positions remain stable, and independent canonical-decoder parity is the required numerical acceptance test.
