Lesson 137 — Handle generated bytes and Unicode safely

Bits to Banking · Umicom Foundation
Author: Sammy Hegab
Topic: Native C23 Transformers, inference and independent validation.

Learning objective: Use the existing reversible tokenizer without treating binary output as text.

1. Understand the engineering problem

The native byte tokenizer maps each byte value 0–255 to a numeric ID by adding four, leaving IDs 0–3 reserved for special symbols. This mapping is reversible. It also means a model can generate a raw byte that is not printable text. An application that inserts a NUL terminator or assumes every output byte is a complete UTF-8 character can silently lose data or display corrupted text.

2. Follow a concrete example

Consider the input byte sequence [0, 67, 10, 255]. The tokenizer maps it to [4, 71, 14, 259]. Byte zero is ordinary source data here, not the reserved PAD token ID zero. After generation, any output token from 4 to 259 can be mapped back to a byte by subtracting four. A four-byte UTF-8 character may arrive across several generated tokens, so even individually valid output bytes need a streaming decoder or buffer before rendering.

3. Implement through the Framework

UmiAiTrainingStackedGenerateBytesNucleus delegates tokenisation to UmiAiByteEncode, uses the same stacked token-generation service and decodes IDs through UmiAiByteDecode. It returns an explicit output byte count and does not add a string terminator. ...SessionNextByte exposes one raw byte for a vocabulary of exactly 260 IDs. Source and destination capacities are measured in bytes here, while the token API capacities are measured in size_t elements.

4. Check the boundaries

Do not execute generated content, treat it as a command, or use it as a banking instruction. Malformed UTF-8 should be handled by a separate presentation layer rather than rewritten inside the tokenizer. When saving a candidate response, retain exact bytes and model identity for repeatable evaluation; never confuse a display conversion with the original model output.

Practice

Question: What token ID represents a byte with numerical value 255?

Reveal the worked answer

The tokenizer adds four: 255 + 4 = 259. The inverse decoder subtracts four to recover 255. The reserved token ID 3 does not represent byte value 3.
