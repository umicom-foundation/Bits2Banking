LESSON 81 · NATIVE C23 · ROTARY POSITION MATHEMATICS

Introduce Rotary Position Mathematics in Native C23

Rotate bounded C23 query and key vectors without altering existing decoder weights.

Learning objectives

Understand why the current Umicom decoder cannot retain learned-absolute key/value rows after a context shift; derive rotary position embedding (RoPE) from ordinary two-dimensional rotation; apply a bounded C23 API; and explain why new mathematics requires a new, explicitly identified model and checkpoint family.

1. Understand the problem before optimising

In Lesson 80, Umicom binds every trained checkpoint to a declared positional strategy and a specific generation convention. The current decoder adds a learned absolute positional embedding to the token embedding at each position. Suppose its context capacity is four. Initially, token 1 occupies position 1; after the oldest token is evicted, it moves to position 0. Because its position embedding changes, its key and value may also change. Simply retaining the old key and value would no longer implement the same mathematical model.

That observation is not a reason to discard earlier work. It tells us to create a different future architecture, while keeping established checkpoint compatibility intact. The previously trained learned-absolute model is not converted by this lesson, and UmiAiTrainingPositionBoundCheckpointDecode must continue rejecting an incompatible sidecar.

2. Rotate a vector pair

Imagine two values, (a,b), as a point on graph paper. Rotating that point by an angle θ changes its coordinates without changing its length:

a' = a × cos(θ) − b × sin(θ)
b' = a × sin(θ) + b × cos(θ)

RoPE applies such rotations to pairs of query and key channels. For pair index j, position p and even rotary width d, the angle in the new bounded research kernel is:

θ(p,j) = p × base^(−2j/d)

For four rotary channels and a base of 10,000, pair zero rotates by p radians while pair one rotates by p/100 radians. At position one, the pair (1,0) becomes approximately (0.540302, 0.841471). At position zero no rotation occurs.

Any trailing non-rotary head channels pass through unchanged. The implementation uses finite double-precision intermediates, materialises FP32 outputs, and refuses input it cannot represent safely. It does not use a second tokenizer, sampler or random generator.

3. Why relative positions matter

For a query at position 6 and a key at position 2, their separation is four positions. Move both to positions 106 and 102: their separation is still four. The dot product of their mathematically rotated vectors is unchanged by this common shift, up to floating-point rounding. This is what enables attention scores to depend on relative separation while keeping absolute positions in the cache.

The lesson's invariant concerns the Q/K rotation. It is not a proof that hidden representations in every transformer layer remain valid after earlier context tokens disappear. In deeper layers, retained token states may incorporate information from evicted tokens. This distinction will decide whether any subsequent cache optimisation is mathematically qualified.

4. Use the reusable Framework C23 primitive

The API lives in include/umicom/ai/training/rotary_position.h and its implementation in src/ai/training/rotary_position.c. Use the public interface rather than copying the angle formula into Studio, Trader, or an application plug-in.

#include "umicom/ai/training/rotary_position.h"
#include <math.h>
#include <stdio.h>

int main(void)
{
    const UmiAiTrainingRotaryConfig cfg = {4U, 4U, 10000.0};
    const float query[4] = {1.0F, 0.0F, 0.2F, 0.7F};
    const float key[4] = {0.5F, 0.3F, 0.4F, -0.1F};
    float rotated[4] = {0};
    double score = 0.0;
    UmiStatus s = UmiAiTrainingRotaryRotate(&cfg, query, 4U, 3U,
                                             rotated, 4U);
    if (s != UMI_STATUS_OK) return 1;
    s = UmiAiTrainingRotaryRelativeDot(&cfg, query, key, 4U,
                                       3U, 1U, &score);
    if (s != UMI_STATUS_OK) return 1;
    printf("rotated Q[0] = %.6f; unscaled Q.K = %.6f\n",
           (double)rotated[0], score);
    return 0;
}

headChannels and rotaryChannels are element counts, not byte lengths. The training laboratory bounds both to a maximum of 32 channels, requires an even rotary width, restricts the frequency base to [2, 1,000,000], and limits absolute positions to 1,048,576. A rejected call leaves the supplied output untouched; identical-buffer in-place rotation is supported through staging.

5. What this does not implement

This module is a mathematical building block, not a rotary-enabled training decoder. It cannot load existing Umicom model weights under new semantics, train a new rotary model, produce complete model logits, or certify end-to-end inference speed. The current decoder, its absolute-position embeddings, sampling APIs, checkpoint codec and 128-byte position sidecar remain unchanged.

6. Verify with real tests

The new rotary_position regression validates position zero, a known trigonometric rotation, unrotated channels, in-place output, relative-shift invariance and equal-position preservation of vector norm. The rotary_rejections regression tests malformed shapes, nonfinite values, unsupported positions and failure-atomic outputs. Both compile as native C23; the public headers can also be included from C++ adapters without changing the C ABI.

7. Practical exercises

  1. For the input pair (0,1), calculate the output after one radian. Explain why the vector's length remains one.
  2. Explain the practical difference between a token's fixed absolute index and its slot in a moving four-token window.
  3. Why would changing the positionEncoding integer in an existing checkpoint declaration be unsafe?
  4. Propose a test comparing two query/key pairs shifted equally by 100 positions. What numerical tolerance would you choose, and why?

Key lesson: rotary position mathematics can make relative-position attention possible, but compatibility with an already trained model must be proved separately.
