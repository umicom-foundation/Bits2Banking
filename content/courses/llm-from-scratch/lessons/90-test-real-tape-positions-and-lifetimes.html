LESSON 90 · NATIVE C23 · ENGINEERING QUALIFICATION

Test Rotary Positions, Tape Lifetimes and Reproducible Training

Learn to distinguish a passing mathematical reference from a reliable, correctly owned training implementation.

1. A correct formula is necessary—but not sufficient

Lesson 89 checked loss and gradients for one training step. A real training library must additionally manage memory lifetimes, output ownership and repeated training iterations. A calculation can be mathematically correct yet still leak memory, return an output from an expired computation graph or change the caller's state after an invalid input.

The new lifecycle regression reuses UmiAiTrainingRotaryOptimisationRun exactly as application code would. It exercises the actual Framework training tape when compiled in your normal native LLM laboratory. It does not instantiate an alternative neural-network implementation.

Mathematics support: Read Maths Unit 15 to learn about relative-position invariance, rounding and evidence. The formula dictionary explains symbols without expecting prior mathematical study.

2. What does positional invariance mean?

Our rotary positional encoding rotates query and key pairs according to their token positions. What matters for their ideal dot product is the difference between positions. If both positions advance by ten places, their distance from one another is unchanged.

(5 − 3) = (15 − 13) = 2

Both pairs have a separation of two token positions. The +10 change moves both together. A correct RoPE implementation should preserve relative query–key scores mathematically. Because computers round, the tests allow a small declared difference rather than assuming universal bitwise equality.

For the three-token teaching problem, the C23 test runs full eight-step training at sixteen different starting positions, beginning from the same query/key weights. It compares the resulting loss trace and updated weights against the baseline within fixed tolerances.

3. Repeat an entire run and check its output

The test creates a fresh tape for every run. The Framework owns its internal tensors. Each call must return a complete result containing exactly eight completed gradient steps, the corresponding post-step losses and finite updated weights. It must not leave a previous training graph alive in application memory.

4. Why compare one-step and eight-step training?

An optimiser moves weights repeatedly. To confirm that a report really describes the intended update count, we compare the result after one step with the first entry of an eight-step run; after two steps with its second entry; and so on. A mismatch would suggest a problem with update order, graph rewinding, loss timing or retained state.

lossAfterStep[n] = loss(recomputed using weights after n+1 updates)

n is a zero-based array index in C, so lossAfterStep[0] is the loss after the first update, lossAfterStep[1] is after the second, and lossAfterStep[7] is after the eighth. The equals sign expresses the API contract, not a prediction that loss will always decrease.

In the Framework, UmiAiTrainingTapeRewind keeps the five original leaf tensors and removes intermediate nodes before the next forward calculation. The updated weights remain; stale computation results are not reused.

5. What must happen on invalid input?

Suppose the key-weight matrix contains a NaN (“not a number”) value. This is not an ordinary weight, and calculations based on it cannot provide trustworthy evidence. The Framework must reject the input and leave the caller's output untouched, rather than return a partly written training report.

/* Native C23 — input is invalid; the output sentinel must survive. */
UmiAiTrainingRotaryOptimisationResult output;
memset(&output, 0xA5, sizeof output);
UmiAiTrainingRotaryOptimisationProblem invalid = original;
invalid.keyWeights[0] = NAN;
UmiStatus status = UmiAiTrainingRotaryOptimisationRun(
    &invalid, &fullPlan, &output);
/* Expect INVALID_ARGUMENT; confirm all output bytes are still 0xA5. */

Neither the C23 implementation nor its public API may rely on PowerShell or Python as a substitute for handling this correctly. PowerShell is used only to invoke the CMake build and tests.

Set-Location 'C:\umicom\Umicom-Applications'

  --target umicom-ai-training-rotary-qualification-oracle-test `
           umicom-ai-training-rotary-qualification-lifecycle-test `

ctest --test-dir '.\build\windows-ucrt64-native-llm-prefix-debug' `
  -R '^framework\.ai\.training\.rotary_qualification_' `
  --output-on-failure --no-tests=error
if ($LASTEXITCODE -ne 0) { throw 'Test failure; investigate before committing.' }

The native demonstration prints each post-step loss and the tape's peak tracked allocation. The independent mathematical reference and lifecycle regressions provide stronger correctness evidence than observing a smaller loss in the demo alone.

7. What remains unproved?

This exercise contains three token rows, four channels and two 4×4 trainable matrices. It does not yet provide a trainable vocabulary-output layer, language-model cross-entropy over a dataset, general decoder checkpoint format, or a production-grade fused RoPE attention tape operator. The original learned-absolute-position decoder and its checkpoints remain unchanged. None of these tests are evidence of general language understanding, production throughput or safety-critical financial accuracy.

8. Practice and solutions

  1. If lossAfterStep[2] is printed, after how many parameter updates was it measured?
  2. Why would comparing only the number of allocated tensors be weaker than running with address and undefined-behaviour sanitisers?
  3. What changes if both position indices advance by +12? What if only the query position advances?
Reveal the instructor's response

lossAfterStep[2] is after the third update because arrays begin at index zero. Tracked allocation counts do not detect every out-of-bounds access or leak; sanitisers provide independent evidence for some classes of fault. Advancing both positions equally preserves the relative difference. Advancing only one changes the difference, which normally changes the position-aware attention score.
