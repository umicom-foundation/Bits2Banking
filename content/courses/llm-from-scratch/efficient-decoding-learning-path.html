Efficient decoding: from one-query attention to modern inference

Author: Sammy Hegab · Service to Many Leads to Greatness.

Previous routeCourse homeCompanion course

Lessons 249–264 continue the native C23 attention course. Learn the bounded forward kernel, independent parity, MQA/GQA, paged and quantised caches, positional schemes, IO-aware attention, speculation and honest serving measurements.

Learning sequence

  1. Implement a forward-only single-query kernel

    Follow one query through a bounded C23 numerical operator without changing a model checkpoint.

  2. Compare a kernel against the canonical last row

    Build a non-circular numerical oracle for a new operator.

  3. Protect capacities, aliasing and atomic results

    Understand the C23 memory contract for safe inference calls.

  4. Separate prefill from incremental decode

    Trace the different workloads for processing a prompt and one new token.

  5. Understand multi-query attention without rewriting a checkpoint

    Distinguish multi-head attention from key/value sharing.

  6. Map grouped-query attention heads

    Calculate the group ownership of each query head.

  7. Measure key/value bandwidth per decode step

    Estimate memory traffic before choosing an optimisation.

  8. Quantise KV caches with an error budget

    Understand reduced-precision storage and how quantisation changes attention.

  9. Understand paged KV memory and block tables

    Explain how non-contiguous cache blocks can represent a logical token sequence.

  10. Distinguish absolute positions from rotary positions

    Explain why changing positional schemes requires architectural and checkpoint compatibility.

  11. Compare IO-aware tiling with single-query streaming

    Distinguish arithmetic work from memory transfers at different context lengths.

  12. Explain speculative decoding and verification

    Understand why draft tokens must be checked against the target model.

  13. Understand continuous batching and request fairness

    Explain latency and throughput trade-offs for several concurrent prompts.

  14. Preserve checkpoint and cache portability

    Describe the identity and layout metadata required to reuse an inference cache.

  15. Measure prefill and decode performance separately

    Produce reproducible latency evidence without confusing different phases.

  16. Complete the native inference qualification capstone

    Bring correctness, numerical analysis, memory ownership and performance measurement together.

How to study

Read the explanation, reproduce the numerical example, answer the question before revealing the explanation, and compare the stated mathematical contract with an independently tested implementation. The worked values are examples, not measured production performance.
