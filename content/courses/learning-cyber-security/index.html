Bits2Banking

Learning Cyber Security

Learn how application inputs, memory ownership and identity checks fit together. The examples use Umicom Framework and a small Bits2Banking consumer. Every chapter explains its vocabulary before the exercise.

Start with assets and trust boundaries, then study buffers, pointer lifetimes, state preservation, local profiles and web sessions. Finish with coding rules, failure tests and a complete feature review. These introductory lessons do not constitute a production authentication service or a security certification.

  1. Identify what an application must protect
  2. Prevent buffer errors at an input boundary
  3. Recognise dangling pointers and define ownership
  4. Keep failed input from changing valid state
  5. Understand local password verification
  6. Design a web login without confusing sessions and passwords
  7. Keep desktop, mobile and broker identity separate
  8. Write coding rules that can be checked
  9. Test rejection, failure and recovery
  10. Review a complete feature from input to effect

Lab: Identities, Credential References and Sessions

Follow an existing C client through metadata registration, bounded text, issuance, current identity checks, expiry and logout. Then design separate web, desktop and mobile adapters without duplicating Framework services.

  1. Read an identity lifecycle from start to finish
  2. Keep credential references inside their buffers
  3. Issue and observe a session without exposing its handle
  4. Check current identity state before a protected action
  5. Test expiry, logout and cleanup precisely
  6. Plan registration and web login around trusted services
  7. Use the same security boundary from desktop and mobile
  8. Review security changes with tests and explicit limits
