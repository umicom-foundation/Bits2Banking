Web development and web servers

Create a small website about a fictional statement. Read what the browser asks for, serve the page with Apache HTTP Server, then run one Java application on Tomcat and WildFly. Lesson 6 follows the same HTTP idea into a native C23 service.

You can read and trace every example before installing anything. For the local exercises, use PowerShell, a text editor and a browser. The Apache and Java exercises list their own tools. Use one practice folder and keep the servers on the same computer as the browser.

Lessons

  1. Make a web page and its stylesheet. Open a saved page and see which file controls its appearance.
  2. Read an HTTP request and response. Find the method, path, status, content type and body.
  3. Serve your page with Apache HTTP Server. Set a document root, test the configuration and request two files.
  4. Deploy a web archive on Apache Tomcat. Compile a small Java request handler and package it with the page.
  5. Deploy the same web archive on WildFly. Compare the result with Tomcat and learn where Red Hat JBoss EAP fits.
  6. Follow a request into native C23. Locate a route in Umicom Framework and compare the evidence from both implementations.
  7. Map the jobs in a deployed website. Decide where a static file, a Java application, a native worker and the browser belong.
  8. Inspect a Red Hat JBoss EAP deployment. Compare a management record with an application response.
  9. Check an Apache configuration copy. Compare the checker’s results for working, incomplete and repaired settings.
  10. Choose the Servlet API for your server. Compile the same servlet for two target API versions and inspect the class.
  11. Follow a request in an access log. Find the requested path and returned status in a short practice log.
  12. Reuse a response with an ETag. Use a saved ETag to decide whether the client needs a new response body.
  13. Set a message for a missing page. Explain a missing page and keep HTTP 404 through the local C host or Apache.
  14. Run a separate local Tomcat instance. Keep a local practice instance’s applications, configuration and logs separate from the server programs.
  15. Serve an XHTML document. Check the document media type and the difference between GET and HEAD.
  16. Send a read-only choice with a form. Read named browser form values in a GET request and compare two responses.
  17. Read form choices in native C. Use the local C route to decode ordinary form values and return the selected practice report label.
  18. Serve two Apache sites on one port. Read two site names in the Apache configuration listing and point them at different folders.
  19. Tell which Apache site answered
  20. Keep links inside an application context
  21. Verify a web archive upgrade and rollback
  22. Read which methods a web route allows
