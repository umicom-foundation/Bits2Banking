Bits2Banking

Connect a menu action to normal refresh

Prepare the exercise

Install a C23 compiler, CMake 3.25 or later, Ninja and a matching Framework SDK containing the restart service. Open a terminal in the lab directory. A terminal runs commands; CMake prepares build instructions and Ninja compiles them. Stop on a configure or build error before using an existing executable. Substitute your own SDK location for the Windows example.

Set-Location "C:\umicom\Umicom-Bits2Banking\labs\native\run-restart"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
cmake -S . -B build -G Ninja -DCMAKE_PREFIX_PATH="C:/umicom/installed/framework"
cmake --build build
.\build\run-restart.exe "$PWD\build\run-restart.exe" handover
ctest --test-dir build --output-on-failure --no-tests=error

In handover mode, expect two controlled executor calls and zero child processes after the old result is retained. Run stop and revoke for one-call refusals. These are expected outcomes to verify, not results asserted for your machine.

Keep the application thin

Studio already has a Run menu, command registry, result collector and notification centre. The restart integration connects those existing parts to Framework. It does not create a second worker or put process termination logic inside a GTK button callback.

Trace the route

The run.restart menu identifier dispatches studio.build.run-restart. Its handler reads current workspace authority and requests the shared intent. Normal UI refresh collects completed results first and then calls Advance. A terminal refusal produces one notification rather than an error that repeats on every idle refresh.

Exercise

Read first_use_run_restart.inc in Studio. The positive scenario invokes the actual menu and waits for a bounded child’s readiness marker to be recreated under a new operation identifier. The revocation case uses the canonical registry directly to create a deterministic gap before GUI refresh. Explain why that gap matters for a repeatable test.

Protect the document

Restart launches the selected existing executable. It must leave an unsaved draft and the saved file unchanged. The native fixture checks both independently. If new source is required, choose Build and Run explicitly. A successful restart does not establish that the running executable corresponds to the current editor buffer.

Review and recover

A missing header or linker symbol requires a matching Framework SDK. For a failed runtime assertion, preserve the command, output and source revision. The four lab cases do not verify native process termination or GUI lifetime; execute the Framework and Studio checks separately before making those claims.
