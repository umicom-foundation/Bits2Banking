Write and run a Pascal program

Course contents · Next: Values, functions and input validation

Your first result

Pascal is a programming language: a vocabulary and grammar for describing operations. In this lesson you will compile a source file and run the resulting program. You do not need to have studied C first.

Prepare the tools

Use the installation summary on the course contents page. Install Free Pascal for your operating system, open a new terminal, and type fpc -iV to check that the compiler can be found. The command should print its version. A missing command means setup is incomplete; it is not a fault in your source.

  1. Open labs/languages/pascal-progress/hello.pas in your Bits2Banking checkout.
  2. Read the program name following program. The semicolon ends that declaration.
  3. Find begin and end. They enclose the main instructions. The final end has a full stop because it finishes the program.
  4. Find WriteLn. It writes text and then moves to a new line.
  5. Build and run using the course commands. Compare the greeting with the source.

A complete practice program

In a separate folder of your choice, save greeting.pas as plain text:

program Greeting;
begin
  WriteLn('Welcome to Learning Pascal.');
end.

Single quotation marks enclose a string: a sequence of characters. The marks themselves are not printed. WriteLn is supplied by the runtime library that accompanies the compiler.

In PowerShell, from that folder:

fpc greeting.pas
.\greeting.exe

In Bash:

fpc greeting.pas
./greeting

Expect Welcome to Learning Pascal. on one line. Compilation may also create an object file. An object file is intermediate machine code used while producing the executable; it is not the source you edit.

Follow the stages

greeting.pas -> Free Pascal compiler -> executable -> printed greeting
edit here                              run this

An editor changes text. A compiler checks and translates that text. A terminal starts the tools. These are separate jobs even when an IDE puts them in one window.

Check the Umicom Pascal Console starter

The greeting exercise calls Free Pascal directly. The Pascal Console Application starter generated by Umicom Studio or Umicom Command uses three separate tools.

ToolWhat it does in the starter
Free Pascal (fpc)Compiles the Pascal source and links a program with its matching runtime units.
CMake (cmake)Reads the project instructions and creates the build plan. The generated project requires CMake 3.26 or newer.
Ninja (ninja)Follows the build plan. The Windows and Linux presets both select Ninja.

  1. Look up the three names before building. Use one of these checks in a fresh terminal.

    Get-Command -Name fpc, cmake, ninja -CommandType Application | Select-Object Name, Source
    for tool in fpc cmake ninja; do
  type -P "$tool" || printf 'Missing from PATH: %s\n' "$tool"
done

  2. Expect a path for each tool. PATH is the list of folders your terminal searches for programs. Compare the reported paths with the folders where you installed the tools. If one is missing, check its installation and open a new terminal after changing PATH.

  3. If your Umicom Command build includes project language-cohort, you can also run this file lookup. In its report, find the developer.language.pascal row and read the three located values.

    umicom project language-cohort

    For example, a search that finds only fpc shows true for fpc and false for both cmake and ninja. That explains why the direct greeting exercise can work while the generated starter still needs two tools.

  4. Treat the report as a file lookup. Three true values establish file presence and leave version, runtime units and linker checks to the actual build. If configure or compilation fails, read the first error and try the relevant step in the generated README. Check the CMake version for configure errors and the selected Free Pascal distribution for missing runtime units or linker errors.

For more practice reading a build plan, see Learning CMake.

Make and explain a change

Add a second WriteLn containing 'Today I will build a small program.'. Predict two lines, compile, then run. Next temporarily remove a closing quotation mark. Read the compiler diagnostic and restore the mark. Do not run an old executable after a failed compilation and assume it includes your change.

Exercise and answer

Why does changing the greeting in the source leave the previous executable unchanged? The executable is a separate file produced by compilation. Recompile successfully before checking the new output.

Help when a command fails

Check the current directory and the exact .pas filename. If fpc cannot be found, revisit installation and PATH. If the output differs, confirm that the file was saved and that you ran the executable from the folder you just compiled.
