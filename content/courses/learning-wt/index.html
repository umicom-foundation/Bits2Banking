Learning Wt

Wt is a C++ library for building web applications with server-side widgets. A browser displays the interface while a server process handles application events. This course builds a small local web application that calls the same Umicom Framework C name-validation service as the desktop lab.

Begin with browser/server communication, build the application, follow session ownership, connect events and examine data boundaries. Finish with a two-session test and a plan for extending the application responsibly. This is a name-validation laboratory, not a deployed registration service.

  1. Browser, server and session
  2. Build and launch the Wt server
  3. Keep each session’s widgets and state separate
  4. Connect web controls to the shared C service
  5. Validate input boundaries and display plain text
  6. Test a local web workflow and record outcomes
  7. Plan registration and login beyond a name checker
  8. Share Framework services across web and desktop

Continue from the form to server operation

Eight further lessons use the same production view to teach automated events, a dedicated public-assets boundary, independent browser contexts, diagnosis and deployment evidence. They distinguish authored checks from outcomes you actually observe.

  1. Build one shared C policy for the web adapter
  2. Exercise production widget events without HTTP
  3. Separate public assets from application source
  4. Observe independent browser sessions
  5. Diagnose transport, resource and event failures
  6. Plan bounded work across a session lifetime
  7. Review deployment and shutdown as separate work
  8. Assemble a web workflow evidence record

The revised lab links the portable Framework C target and can check widget events through Wt::Test. HTTP, browser, session and deployment observations remain separate steps.
