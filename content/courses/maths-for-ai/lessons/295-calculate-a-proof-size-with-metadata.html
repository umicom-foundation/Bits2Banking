Concept and mechanism

An inclusion proof contains sibling hashes plus an index and count. The current native C structure reserves ten 32-byte sibling slots even if fewer are used. Its in-memory size may include size_t fields and padding; do not claim a portable network size by applying sizeof to a C struct. A portable transport must specify field widths explicitly.

Worked example

For five records: sibling hashes=3×32=96 bytes. With a designed frame of BE64 index and BE64 count, the compact metadata adds 16 bytes, producing 112 bytes before signature, root or length headers.

Where the proof stops

The demonstration has no signed Merkle wire protocol; these sizes describe a proposed serialisation.

A native test can verify byte-level membership but cannot by itself authenticate a participant, authorise financial transactions, establish consensus or prove neural model improvement. Record the independent root, protocol and unperformed tests.

Native implementation boundary

Use the existing Umicom Framework C23 SHA-256 and ordered record chain. The opt-in Merkle service consumes validated digests and exposes bounded membership checks. Existing Python and PowerShell teaching tools remain alternatives, not the implementation.
