FOUNDATION MATHEMATICS · UNIT 18 OF 18

Memory budgets, peak allocation and safe rollback

Understand why a training program must release temporary work after an error.

Designed for all educational backgrounds. No previous university mathematics or AI experience is assumed. When a symbol is new, its meaning is explained before it is used.

1. A memory budget is like a spending limit

Suppose an Umicom application gives one process a budget for working memory. It must not allocate unlimited storage merely because it can calculate a result. The same principle applies to a training tape: tensor values, gradients and some saved intermediate information occupy memory.

Memory accounting is not the same as the total memory reported by Windows Task Manager. The Framework's tape measurements describe specific tracked allocations that it owns, not every part of the process.

2. Current allocation versus the historic peak

MeasurementWhat it meansExample
Current bytesStorage currently retained by the tape1,200 bytes
Peak bytesLargest tracked current allocation reached so far1,800 bytes
Budget bytesMaximum permitted tracked allocation, when enabled1,900 bytes
Capacity rulecurrentBytes + requestedBytes ≤ budgetBytesCurrent means memory already in use. Requested means the new allocation. Budget is the configured maximum. The ≤ sign means the combined amount must be no larger than the budget.

For current 1,200 bytes, a request for 600 bytes and a 1,900-byte budget, 1,200+600=1,800≤1,900, so the request fits. A request for 800 bytes gives 2,000>1,900 and should be refused.

3. Why rollback does not erase the peak

Imagine a calculation begins with 1,200 bytes. It briefly reaches 1,800 bytes and then an operation fails. The Framework releases the temporary nodes and returns to 1,200 bytes.

Rollback statecurrent: 1,200 → 1,800 → 1,200; peak: 1,800The arrows show the timeline. The current value decreases when allocations are released; the peak remains at 1,800 because it records the highest amount ever reached.

The fact that the peak remains high is not evidence that memory has leaked. A leak investigation needs repeatable current allocations, lifetime checks and external tools.

4. Why an incomplete answer must never be published

Suppose the training calculation needs four stages. If stage three runs out of memory, the Framework must not return an apparently successful output from stage two. Otherwise a caller might mistake incomplete data for a correct result.

A failure-atomic operation either publishes the complete new result or leaves the caller's published output unchanged. Intermediate allocations are released through the owning tape's rollback contract.

5. A simple C23 engineering check

UmiAiTrainingTapeMemory before = {0};
UmiAiTrainingTapeMemory after = {0};
UmiStatus status = UmiAiTrainingTapeMemoryInspect(tape, &before);
if (status != UMI_STATUS_OK) return 1;
/* Perform a Framework rotary operation and, on failure,
   verify that rollback restored the expected retained nodes. */
status = UmiAiTrainingTapeMemoryInspect(tape, &after);
if (status != UMI_STATUS_OK) return 1;

This is explanatory C23, not a complete executable test. The full regressions in the Framework package create real tensor handles, use the public memory-budget contract and check both the graph count and current allocation.

6. Why sanitiser testing is a separate check

A memory counter can look normal even if a program briefly reads beyond an array boundary. AddressSanitizer can detect many invalid accesses, while UndefinedBehaviourSanitizer checks additional classes of undefined behaviour. Neither replaces correct ownership rules or proves a program is free from all bugs.

The Windows native build, Linux builds, and any sanitiser configuration must be reported independently. A successful test against an API-compatible demonstration does not establish that the production Framework passed.

7. Practice with worked answers

  1. The current allocation is 1,250 bytes, the budget is 2,000 bytes and a new tensor needs 900 bytes. Does it fit?
  2. A tape reaches 1,900 bytes, then rolls back to 1,250. What is the peak afterwards?
  3. Why should an output pointer remain unchanged if the tape fails while assembling a result?
Reveal the worked answers

1. 1,250+900=2,150; it exceeds 2,000 and must be refused. 2. The peak remains 1,900 bytes: it records the highest observed tracked allocation. 3. Publishing only complete outputs prevents downstream software from using an incomplete, misleading result.
