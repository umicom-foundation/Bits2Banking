What you will learn

Explain derive the duplicate-last rule for odd numbers of leaves with explicit assumptions, an independently checkable worked example and the limits of the evidence.

Concept and mechanism

For a level with an odd number of nodes, the final node is paired with itself to make a binary parent. Its sibling path can therefore include a digest equal to the node at that level. This is a documented tree convention, not an extra business record, and is distinct from adding a duplicate input leaf.

Worked example

Five logical leaves become three parents, then two parents, then one root node; the last leaf follows E→H(E,E)→H(P2,P2)→root.

Try it yourself

Explain the first sibling for index 4 in a five-leaf input.

Reveal the fully worked answer

It is the hash of that same leaf node because index 5 is out of range at that level.

Where the proof stops

Different Merkle designs make different choices for odd nodes; importing proofs without scheme identification is unsafe.

A native test can verify byte-level membership but cannot by itself authenticate a participant, authorise financial transactions, establish consensus or prove neural model improvement. Record the independent root, protocol and unperformed tests.

Native implementation boundary

Use the existing Umicom Framework C23 SHA-256 and ordered record chain. The opt-in Merkle service consumes validated digests and exposes bounded membership checks. Existing Python and PowerShell teaching tools remain alternatives, not the implementation.
