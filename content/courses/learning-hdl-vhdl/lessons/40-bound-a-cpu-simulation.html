Distinguish successful completion from a timeout

What you will learn

A simulation can stall because an expected event never occurs. A deadline prevents the test from waiting forever. Successful completion must be explicit, so that merely stopping the simulator is not mistaken for success.

Set up this exercise

A terminal is a window in which you type commands. A folder holds the files of a project. Install Git, CMake 3.26 or later, Ninja and GHDL with VHDL-2008 support; make their executable folders available on PATH. PATH is the list of folders the terminal searches for programs. Open a fresh PowerShell or Bash terminal and check:

git --version
cmake --version
ninja --version
ghdl --version

Each command should print a version. If a command is not found, correct its installation or PATH before continuing. Download the Bits2Banking repository with Git if you do not already have it:

git clone https://github.com/umicom-foundation/Bits2Banking.git
cd Bits2Banking/labs/hardware/vhdl-cpu

If you already have the repository, open its labs/hardware/vhdl-cpu folder instead of cloning again. Work in your own practice copy. The following commands are identical in PowerShell and Bash:

cmake --preset simulation
cmake --build --preset simulation
ctest --preset simulation

Configure finds GHDL and writes build instructions. Build analyses the VHDL files. Test runs the simulated circuit and checks its results. Expected: the cpu.instructions test passes. This is a learner check to perform on your computer, not a claim about a supplied binary. To select a GHDL installation outside PATH, configure with a quoted absolute path:

cmake --preset simulation "-DGHDL_EXECUTABLE=C:/tools/ghdl/bin/ghdl.exe"

A simulation predicts the behaviour described by a model. It does not program a physical chip. No hardware board is required for this module.

Find both endings

The stimulus reports CPU checks passed and calls finish after its assertions. A separate process waits for two microseconds and then raises a failure. That process is independent of the instruction-driving procedure.

process
begin
  wait for 2 us;
  assert false report "CPU test exceeded its deadline" severity failure;
end process;

A microsecond is one thousand nanoseconds. The normal instruction sequence takes much less than two microseconds in this model.

Understand the second limit

CMake also sets the CTest timeout to 15 seconds. This is real elapsed time on the computer. It protects against a tool that hangs or stops advancing simulated time.

The two limits answer different questions. The VHDL deadline asks whether the model reached completion within its simulated schedule. The CTest timeout asks whether the program finished within an acceptable wall-clock duration.

Practice a stalled input

In a practice copy, replace the clock generator with a constant clock. Run CTest. The CPU stimulus will wait for a rising edge that never occurs, while the independent simulated-time deadline can still report failure.

Do not change the expected result to a pass. Restore the clock and run again. A timeout is missing evidence, not a successful instruction test.

Troubleshoot

If the window appears frozen, inspect the test output and the CTest deadline before rerunning the entire repository. Keep the command, exit status and test name with your notes. A test that never reaches its assertions cannot establish CPU correctness.

Check your understanding

Why not use only a simulator stop-time and call every stopped run successful? A stop-time can end a run before required assertions or completion were reached. The explicit finish point and failing deadline make that distinction visible.
