Bits2Banking

Create a CPU simulation project in Studio

What you will learn

A CPU is a circuit that follows instructions. An instruction is a small encoded operation such as adding a number or selecting the next instruction address. In this project you will inspect a small eight-bit CPU and run checks that explain what each operation does. Eight-bit means the accumulator stores eight binary digits, enough for unsigned values from 0 to 255.

Set up this exercise

A terminal is a window in which you type commands. A folder holds the files of a project. Install Git, CMake 3.26 or later, Ninja and GHDL with VHDL-2008 support; make their executable folders available on PATH. PATH is the list of folders the terminal searches for programs. Open a fresh PowerShell or Bash terminal and check:

git --version
cmake --version
ninja --version
ghdl --version

Each command should print a version. If a command is not found, correct its installation or PATH before continuing. Download the Bits2Banking repository with Git if you do not already have it:

git clone https://github.com/umicom-foundation/Bits2Banking.git
cd Bits2Banking/labs/hardware/vhdl-cpu

If you already have the repository, open its labs/hardware/vhdl-cpu folder instead of cloning again. Work in your own practice copy. The following commands are identical in PowerShell and Bash:

cmake --preset simulation
cmake --build --preset simulation
ctest --preset simulation

Configure finds GHDL and writes build instructions. Build analyses the VHDL files. Test runs the simulated circuit and checks its results. Expected: the cpu.instructions test passes. This is a learner check to perform on your computer, not a claim about a supplied binary. To select a GHDL installation outside PATH, configure with a quoted absolute path:

cmake --preset simulation "-DGHDL_EXECUTABLE=C:/tools/ghdl/bin/ghdl.exe"

A simulation predicts the behaviour described by a model. It does not program a physical chip. No hardware board is required for this module.

Find the parts of the project

FilePurpose
rtl/learning_cpu.vhdDescribes the CPU and the state it retains between clock edges.
tests/tb_learning_cpu.vhdSupplies inputs and checks the resulting outputs.
CMakeLists.txtDefines the analysis and simulation commands.
CMakePresets.jsonGives those commands the reusable name simulation.
README.mdSummarises the instruction encoding and commands.

The testbench is a second VHDL design that surrounds the CPU. It acts as both a driver, supplying inputs, and an observer, checking outputs.

Create the same project from Studio

  1. Open Umicom Studio IDE and choose New Project.
  2. Select VHDL CPU Simulation from the project templates.
  3. Enter Learning CPU as the application name, org.umicom.learning.cpu as the application ID, learning-cpu as the repository name and learning_cpu as the target name.
  4. Choose an empty practice folder that you control.
  5. Review the generated files before creating the project.
  6. Select the simulation preset for Configure, Build and Test.

The application ID is a stable name for the project; it is not a login account. The repository name is suitable for the folder, while a target is a named build operation. Framework owns the template and language description, allowing Studio to discover them through its existing project catalogue.

The native Run command expects an executable program. Use Test for this hardware model, or run the simulate build target from the terminal. If the template is missing, check that your Studio build includes the Framework VHDL template. The terminal path above remains usable independently.

Inspect the shared implementation

Open Framework's src/developer_project/templates/vhdl_cpu.c and src/developer_project/languages/vhdl.c. The template returns file descriptions; the language pack declares analysis and testing capabilities. It does not claim a debugger, synthesis service or FPGA upload command.

Check your understanding

Why do we need a testbench as well as a CPU file? The CPU file describes a circuit. The testbench supplies a sequence of inputs and checks whether the circuit behaves as intended. Merely parsing the CPU file does not exercise its instructions.
