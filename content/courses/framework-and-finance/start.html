Start your connected learning journey

You do not need a banking account, trading subscription or previous software job to read these lessons. A computer stores information, a program follows instructions, and a file is named information stored on a device. A folder groups files. The examples build from those ideas.

Choose a route

  1. Start with Framework Architecture to learn how applications share services.
  2. Follow Studio, Data and Security for the software route. For the finance route, begin with Banking and Payments.
  3. Read the explanation and trace the diagram before inspecting code. A word in the glossary is a reference you can revisit.
  4. Complete the exercise using fictional information. Read the worked answer only after trying it.
  5. Finish with Financial-System Integration, which joins records, commands, evidence and review.

Read in a browser

  1. Open your Bits2Banking folder.
  2. Open content/courses/framework-and-finance/index.html in a browser.
  3. Select a course, then its first lesson. Previous, Next and Course overview links keep the route connected.

Read in Umicom Studio IDE

  1. Open Guided Learning and choose Open local learning catalogue. You may also choose Follow Bits2Banking courses on the welcome page when supplied with your Studio build. After loading the pack, choose that button again to open its course overview.
  2. Choose the absolute folder containing this collection’s learning-pack.json. For the usual checkout, it is C:\umicom\Umicom-Bits2Banking\content\courses\framework-and-finance. Choose your own location if it differs.
  3. Select Load learning pack. Search by a title or topic, select a result and choose Open selected.
  4. Follow declared local links to another lesson. Back and Forward return through the reading history. The native reader shows structured text; a browser supplies the full page styling.

The Framework reader verifies the declared bytes before displaying a page. It does not execute examples. This pack declares Framework compatibility 0.9.0; a different version needs a reviewed compatibility update. Missing or changed files, unsupported versions and paths outside the selected pack are reported rather than silently accepted.

Keep progress in a location you choose

  1. Expand Private learning checkpoints in the catalogue.
  2. Choose your own checkpoint database filename in a folder you can access.
  3. Select a lesson. Enter a Local learner ID such as learner-1, a Checkpoint ID such as reviewed, and an Evidence reference such as exercise-1. These are short identifiers; keep notes separately.
  4. Use Inspect checkpoint to read the existing record, or Record checkpoint to append the completed activity. Inspect does not create a missing database. The parent folder must already exist.
  5. Keep exercise source in a separate practice folder you choose. Recording progress does not compile or run a project.

A checkpoint is a local learning record, not a certificate or proof that an application works. The catalogue’s loaded packs and reading history belong to the current window; reopen the folder after a new session. No account or upload is required for these lessons.

When something does not open

  • No manifest: choose the collection folder, not its parent or an individual lesson.
  • Checksum mismatch: the files differ from the declared edition. Obtain a consistent pack or, if you maintain the course, regenerate the manifest after reviewing the changed content. Do not disable verification.
  • Unsupported version: check the manifest’s compatibility range against your Framework build.
  • Studio button does nothing: use the browser route to continue reading and record the command and observed result for investigation.
  • External course does not open in the native reader: only declared files inside this pack are admitted. Use the browser course library for other courses.
