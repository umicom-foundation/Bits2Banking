# Describe a service restart boundary

![Umicom Foundation](../../assets/branding/umicom-wordmark.svg){ .umicom-wordmark .umicom-wordmark-light width="215" }
![Umicom Foundation](../../assets/branding/umicom-wordmark-on-dark.svg){ .umicom-wordmark .umicom-wordmark-dark width="215" }

A classroom service has one waiting request and one previously completed result when it restarts.

1. Record which result is complete and which request has no reply. Draw where the restart belongs on the timeline.
2. Trace the post-restart service readiness and identify what the caller must check before treating an old request as complete.

**Check your result.** The completed result stays in the earlier record. The pending request needs matching new evidence before being marked complete.
