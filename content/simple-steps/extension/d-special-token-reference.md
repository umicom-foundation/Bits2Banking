# Record the toolchain with two teaching versions

![Umicom Foundation](../../assets/branding/umicom-wordmark.svg){ .umicom-wordmark .umicom-wordmark-light width="215" }
![Umicom Foundation](../../assets/branding/umicom-wordmark-on-dark.svg){ .umicom-wordmark .umicom-wordmark-dark width="215" }

The D compiler report needs a stable way to distinguish two edits to the teaching fixture.

1. Add writeln("fixture 3") to a scratch copy of the vendor and version sample. Duplicate the file and use fixture 4 in the duplicate.
2. Build both with the same configured compiler, or label two rows of the course's sample output on paper. Compare the source marker, vendor and encoded version columns.

**Check your result.** The first line reads fixture 3 for the first source and fixture 4 for the second. The vendor and encoded version match across these two builds.
