# Check the returned C status before updating the screen

![Umicom Foundation](../../assets/branding/umicom-wordmark.svg){ .umicom-wordmark .umicom-wordmark-light width="215" }
![Umicom Foundation](../../assets/branding/umicom-wordmark-on-dark.svg){ .umicom-wordmark .umicom-wordmark-dark width="215" }

A fictional Swift editor starts with count 4. Its C fixture accepts the first operation and returns count 6. A second fixture returns refusal with no published value.

1. Use the workflow lesson to specify two separate tests starting from count 4. Give the case fixtures the stated return status and result.
2. Check the count and feedback after each call. Read a returned value only in the accepted case.

**Check your result.** The accepted case shows 6 and Ready. The refused case keeps 4 and displays the scratch fixture’s message Cannot update.
