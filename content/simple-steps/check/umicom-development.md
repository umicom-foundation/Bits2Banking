# Check a valid report and refused replacement

![Umicom Foundation](../../assets/branding/umicom-wordmark.svg){ .umicom-wordmark .umicom-wordmark-light width="215" }
![Umicom Foundation](../../assets/branding/umicom-wordmark-on-dark.svg){ .umicom-wordmark .umicom-wordmark-dark width="215" }

A local installed-SDK example has a known good input file and a second file that fails its validator.

1. Run or trace both using separate disposable paths. Record how the report and status are produced in each case.
2. Check whether a refused input can provide a replacement result in the workshop’s contract.

**Check your result.** Only the valid input produces the complete expected report. The refusal remains separate from that report.
