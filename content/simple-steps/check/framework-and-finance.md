# Check that a runtime result has execution evidence

![Umicom Foundation](../../assets/branding/umicom-wordmark.svg){ .umicom-wordmark .umicom-wordmark-light width="215" }
![Umicom Foundation](../../assets/branding/umicom-wordmark-on-dark.svg){ .umicom-wordmark .umicom-wordmark-dark width="215" }

A practice release note has two rows. The first shows a composed build command and predicted output. The second also contains the executed command, captured output and exit status 0 for the same exercise.

1. Use Build and Runtime Diagnostics from the learning collection to identify which row documents an actual process outcome.
2. Write labels for both records before adding them to your learning checkpoint.

**Check your result.** The first is a planned check with no observed result. The second records an executed observation with status 0.
