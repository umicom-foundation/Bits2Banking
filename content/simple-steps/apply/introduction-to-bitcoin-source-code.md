# Make a code-reading card for one validation rule

![Umicom Foundation](../../assets/branding/umicom-wordmark.svg){ .umicom-wordmark .umicom-wordmark-light width="215" }
![Umicom Foundation](../../assets/branding/umicom-wordmark-on-dark.svg){ .umicom-wordmark .umicom-wordmark-dark width="215" }

A workshop source map and a fixed Bitcoin revision are available. A paper regression fixture gives an output a negative amount.

1. Find the output amount check in the basic transaction checks and record the revision, source path and function name on a card.
2. Explain which result the fixture reaches and write the different expected action for a nonnegative amount at that same check.

**Check your result.** The card identifies the check and records rejection for the negative amount. The nonnegative example continues beyond that check.
