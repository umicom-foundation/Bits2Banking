# Conda and Miniforge for Umicom Developers

![Umicom Foundation](../../assets/branding/umicom-wordmark.svg){ .umicom-wordmark .umicom-wordmark-light width="215" }
![Umicom Foundation](../../assets/branding/umicom-wordmark-on-dark.svg){ .umicom-wordmark .umicom-wordmark-dark width="215" }

1. Write down which project needs a separate Python environment and why its packages should be kept separate. [Choose an environment tool for the job](../../courses/conda-miniforge-for-developers/lessons/01-choose-an-environment-tool.html)
2. With Conda already available, use `conda env list`. Find `umicom-env-lab` or inspect the lesson’s dry-run plan for it. [Create an environment and identify its interpreter](../../courses/conda-miniforge-for-developers/lessons/04-create-and-inspect-an-environment.html)
3. If the practice environment exists, activate it and use the lesson’s Python command to print both interpreter and environment paths. [Create an environment and identify its interpreter](../../courses/conda-miniforge-for-developers/lessons/04-create-and-inspect-an-environment.html)

**Check your result.** The plan names `umicom-env-lab` and Python 3.12. In an existing environment, both printed paths point into that environment.
