# Learning XML

![Umicom Foundation](../../assets/branding/umicom-wordmark.svg){ .umicom-wordmark .umicom-wordmark-light width="215" }
![Umicom Foundation](../../assets/branding/umicom-wordmark-on-dark.svg){ .umicom-wordmark .umicom-wordmark-dark width="215" }

1. Copy the lesson’s short XML example. Match each opening tag to its closing tag and repair the supplied broken example. [Read and repair an XML document](../../courses/learning-xml/lessons/01-read-and-repair-a-document.html)
2. Open the sample project file. Write down the namespace URI and local element name beside one element. [Understand XML namespace identity](../../courses/learning-xml/lessons/02-understand-namespace-identity.html)
3. Trace the valid XML that lacks a required application field. Record the parser’s result separately from the application’s decision. [Separate parsing from application validation](../../courses/learning-xml/lessons/03-separate-parsing-from-application-validation.html)
4. Open the sample test report. Find the suite name, number of tests and recorded failures before writing your result. [Interpret an XML test report as evidence](../../courses/learning-xml/lessons/04-interpret-a-test-report-as-evidence.html)

**Check your result.** The repaired XML parses. Your notes explain why a well-formed document can still fail the application’s checks.
