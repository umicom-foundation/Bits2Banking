# Safer C Programming

![Umicom Foundation](../../assets/branding/umicom-wordmark.svg){ .umicom-wordmark .umicom-wordmark-light width="215" }
![Umicom Foundation](../../assets/branding/umicom-wordmark-on-dark.svg){ .umicom-wordmark .umicom-wordmark-dark width="215" }

1. Write the lesson’s starting length and capacity. Trace an insert of one byte, then an insert of two. [Bounds and preserving state on failure](../../courses/safer-c-programming/lessons/01-bounds-and-failure-preservation.html)
2. Open the editor move example. Mark the overlapping spans and identify the copy operation chosen for them. [Overlapping memory and ownership](../../courses/safer-c-programming/lessons/02-overlap-and-ownership.html)
3. Use the controlled file-write failure in the lesson. Check that the earlier complete result is still available. [Numbers, file writes and useful checks](../../courses/safer-c-programming/lessons/03-numbers-files-and-checks.html)

**Check your result.** The 1,023-byte case accepts one extra byte and declines two while preserving the earlier state.
