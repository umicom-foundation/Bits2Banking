# Introduction to Operating Systems

![Umicom Foundation](../../assets/branding/umicom-wordmark.svg){ .umicom-wordmark .umicom-wordmark-light width="215" }
![Umicom Foundation](../../assets/branding/umicom-wordmark-on-dark.svg){ .umicom-wordmark .umicom-wordmark-dark width="215" }

1. Write down the operating system running your terminal and which program opened it. [Understand programs and the resources they use](../../lessons/08-system-administration/introduction-to-operating-systems/01-programs-and-resources.md)
2. Read the lesson’s Windows-to-RISC-V example. Fill in three labels for development host, build target and emulator guest. [Distinguish the development host, guest and build target](../../lessons/08-system-administration/introduction-to-operating-systems/02-host-guest-and-target.md)
3. Draw the boot sequence from firmware to the first console. Add the output you would look for at the last stage. [Follow the path from firmware to a working console](../../lessons/08-system-administration/introduction-to-operating-systems/03-follow-the-boot-chain.md)

**Check your result.** Your notes put Windows on the host, RISC-V at the build target and QEMU on the emulator line. The boot drawing ends at the guest console.
