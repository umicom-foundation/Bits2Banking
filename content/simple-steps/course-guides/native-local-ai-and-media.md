# Native Local AI Chat and Media with Umicom Framework

![Umicom Foundation](../../assets/branding/umicom-wordmark.svg){ .umicom-wordmark .umicom-wordmark-light width="215" }
![Umicom Foundation](../../assets/branding/umicom-wordmark-on-dark.svg){ .umicom-wordmark .umicom-wordmark-dark width="215" }

1. Trace one local message through the policy, provider, engine and display boxes in the lesson. [Read a local AI project before designing your own](../../courses/native-local-ai-and-media/lessons/01-read-a-local-ai-project.html)
2. Open the shared API and identify the check the request passes before generation. [Map shared Framework services to AI applications](../../courses/native-local-ai-and-media/lessons/02-map-framework-and-applications.html)
3. Predict the outcome for the offline lab fixtures, then compare how the catalogue handles a capability the provider lacks. [Select capabilities and budget context](../../courses/native-local-ai-and-media/lessons/03-select-capabilities-and-budget-context.html)

**Check your result.** Your drawing identifies who owns the request and who returns the result. An unavailable capability stops before generation.
