# Learning Build and Runtime Diagnostics

![Umicom Foundation](../../assets/branding/umicom-wordmark.svg){ .umicom-wordmark .umicom-wordmark-light width="215" }
![Umicom Foundation](../../assets/branding/umicom-wordmark-on-dark.svg){ .umicom-wordmark .umicom-wordmark-dark width="215" }

1. Put four headings on a notes page for configure, compile, link and test. [Read each stage of a build](../../courses/framework-and-finance/builds-and-diagnostics/lessons/build-evidence.html)
2. Take the lesson’s build errors in order. Put the missing declaration under compile and the missing symbol under link. [Read each stage of a build](../../courses/framework-and-finance/builds-and-diagnostics/lessons/build-evidence.html)
3. If the link step produced no executable, record the dependent test as not run and keep the original diagnostic. [Read each stage of a build](../../courses/framework-and-finance/builds-and-diagnostics/lessons/build-evidence.html)

**Check your result.** The written record shows a link failure and an unexecuted test, with the evidence for each stage kept separate.
