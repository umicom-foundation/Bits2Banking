# Community learning: your first development steps

Let us start with one small task at a time. You do not need programming experience. The first step is opening a terminal and finding your current folder. Each lesson explains what to type, what the command means and what you should see.

Work in a practice folder you choose. Stop and check the result before moving on. If something is unfamiliar, use the explanation on the same page; the related courses are there when you want more detail. Existing courses and lessons remain available.

## Follow the route

1. [Open PowerShell and find your place](lessons/01-open-your-terminal.md) — Open a terminal, identify the shell and find the folder it is using.
2. [Make a folder for your practice work](lessons/02-make-a-practice-folder.md) — Create a practice folder and move into it without touching product source.
3. [Write and read your first Markdown file](lessons/03-write-your-first-readme.md) — Create a README, add a sentence and open it in a text editor.
4. [Copy, rename and preview a deletion](lessons/04-copy-and-preview-changes.md) — Keep a practice copy and understand what a file command will change.
5. [Install and find your everyday tools](lessons/05-install-and-find-tools.md) — Check PowerShell, Git, GitHub CLI and an editor without installing duplicates.
6. [Record two versions with Git](lessons/06-make-two-local-commits.md) — Create a local repository, inspect a change and record two commits.
7. [Share a practice project and clone it](lessons/07-share-and-clone-a-project.md) — Publish your own practice repository deliberately, then download a separate copy.
8. [Set up the Windows C toolchain](lessons/08-set-up-the-c-toolchain.md) — Use one consistent compiler, build system and library environment.
9. [Write, compile and run a C program](lessons/09-build-your-first-c-program.md) — Turn a small C source file into an executable and recognise each step.
10. [Build and test a small notes project](lessons/10-build-and-test-a-small-project.md) — Separate reusable C behaviour from its caller and test the boundary.
11. [Follow a button into Umicom Framework](lessons/11-follow-a-framework-button.md) — Trace a real desktop action from its button to the shared Framework function and its regression test.
12. [Read a build log and choose the next step](lessons/12-read-a-build-log.md) — Tell configuration, compilation and test failures apart and keep evidence of the first useful diagnostic.

## Choose how you learn or teach

Every lesson has a Markdown page, a [printable HTML handout](handouts/index.html), a video teaching script and a short community message. The lesson links connect these editions. The scripts describe what to show, what to say and where to pause; they are not recordings of a working product.
