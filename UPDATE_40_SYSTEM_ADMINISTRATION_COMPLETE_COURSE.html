Chapter 01 — What does a system administrator do?

What you will learn

Identify the responsibilities of someone who keeps a computer useful, secure and recoverable.

Why this matters

A system administrator keeps computers and services dependable for the people who rely on them. That may mean setting up an account for a new colleague, explaining why an application will not launch, checking whether a disk is nearly full, confirming that a backup can be restored, or investigating unusual activity. A household computer needs the same principles on a smaller scale. A school computer room, a charity office and a bank apply them to more people and higher consequences.

Administration is not the same as programming. A developer changes how software works. An administrator installs, configures, monitors and protects the environment where software runs. The roles overlap: a Umicom contributor who compiles a C23 application also needs to understand storage, permissions, running processes and logs.

A useful professional habit is to separate observation from change. Looking at free disk space is observation. Deleting old files is a change. Before a change, know what system it affects, what success looks like, how you could undo it and whether you are authorised to perform it.

Term Plain-English meaning
System The computer, its operating system, installed software, data, users and connected services.
Service A program that supplies a capability, often without a visible window.
Availability Whether people can use the service when they need it.
Backup A separate recoverable copy of data.
Least privilege Having only the access needed for a task.

Chapter 02 — Understand the computer, operating system and user account

Bits to Banking · System Administration: From Zero · Umicom Foundation

What you will learn

Explain hardware, the operating system, applications and accounts as separate layers.

Why this matters

A computer has physical components such as a processor, memory, a drive and a network interface. The operating system coordinates these components and supplies standard services. Applications use those services to open files, display windows, send network requests and use memory. Your user account controls the identity and permissions under which an application acts.

It helps to picture the layers from bottom to top: hardware, operating-system kernel and drivers, operating-system services, applications and the person using them. If a text editor cannot save a document, the cause may be inside the editor, a directory permission, a full drive or a read-only file. One symptom can have several possible causes.

Windows and Linux organise these concepts differently. Windows normally shows drives such as C: and uses backslashes in paths. Linux usually presents a single directory tree rooted at /. Neither choice tells you whether a file is safe to delete. Always inspect the actual path and ownership first.

New words, explained

Term Plain-English meaning
CPU Processor that executes instructions.
RAM Working memory used while programs run.
Storage Persistent space for files and installed software.
Kernel Privileged part of the operating system that controls hardware and processes.
Account Identity whose access rights are checked by the operating system.

Identify the program you have opened before typing unfamiliar commands.

Why this matters

The screenshot below is from the supplied Windows search example. It shows why the programme name and version matter more than the colour of the icon.

A terminal window is a way to communicate with the shell. The shell reads a command, invokes a built-in operation or an external program, and displays the result. A command is not automatically a script. We use individual interactive PowerShell commands for learning and administration; all new Umicom executable implementations remain in C23 or Assembly.

What you will learn

Understand the pieces of a command and find trusted documentation.

Why this matters

A command normally contains a command name followed by arguments or options. In Get-ChildItem -Path "$HOME", Get-ChildItem is the operation and -Path is the name of a parameter. The quoted folder is the value of that parameter. In git --version, --version is an option recognised by Git, not a PowerShell parameter. Different programs have different option styles.

PowerShell commands are called cmdlets when they follow the verb-noun naming convention, such as Get-Process and Test-Path. It also runs native executables such as git.exe and cmake.exe. A vertical bar | passes output to another command; you can use it to select columns rather than read pages of detail.

Before using an unfamiliar command, prefer Get-Help, the program’s --help output and its official documentation. Treat copied commands from chats and websites as proposals to review, not instructions to execute blindly. If an option looks like it deletes, formats, force-pushes or rewrites history, do not execute it during a beginner exercise.

New words, explained

Term Plain-English meaning
Parameter Named input to a command, such as -Path.
Argument A value passed to a command or executable.
Pipeline A connection that passes command output to another command.
Alias An alternate name, such as pwd for Get-Location in PowerShell.
Exit code A number indicating whether a native program succeeded.

What you will learn

Create a private training directory and understand absolute and relative paths.

Why this matters

A folder groups files and other folders. The working directory is the location where relative paths are interpreted. An absolute Windows path such as C:\Users\Alex\UmicomLearning identifies a location without depending on where you started. A relative path such as notes\README.md begins inside the current directory. You can get unexpected results if you change files while standing in the wrong location.

We deliberately use $HOME\UmicomLearning for examples. $HOME is your account’s personal home folder, so the exercise does not touch your real C:\umicom\Umicom-Applications workspace or require administrator privileges. $HOME expands to a path that can contain spaces; the quotation marks keep that path together.

Get-Location and pwd observe the current directory. Set-Location and cd change it. New-Item -ItemType Directory creates a folder. Test-Path checks whether one exists. Do not use git submodule add as a synonym for creating a regular folder: it registers a separate Git repository and needs more careful review.

What you will learn

Create a Markdown note, read its contents and recognise file extensions.

Why this matters

A text file stores characters. A Markdown document (.md) is plain text with conventions for headings, links and lists. A C source file (.c) is also text but is interpreted by a compiler rather than a documentation renderer. A word-processing document (.docx) uses a different structured format. System administrators frequently inspect configuration and log files, so distinguishing these formats matters.

In the practice folder, use Notepad to create a short README.md. You do not need to write a PowerShell script to make this file. You can also write a short line interactively using Set-Content. However, the course does not create .ps1 or Python implementation files.

PowerShell Get-Content displays a text file. Get-Item reports file metadata such as size and modification time. Get-FileHash calculates a fingerprint used later when learning backup verification. Opening a text document is normally a reversible, low-risk activity, but opening an unknown executable or script is not equivalent.

What you will learn

Identify the layers involved when a computer connects to a website or service.

Why this matters

A network connects devices that exchange messages. An IP address identifies a network interface in the relevant routing context. A router forwards traffic between networks. DNS maps names such as github.com to addresses. A TCP port identifies a service endpoint, such as port 443 commonly used for HTTPS. An HTTP application works above these layers.

Diagnostics should favour observation and approved destinations. This chapter uses public documentation domains as examples but does not imply that they are always reachable from every network. Avoid scanning arbitrary hosts or internal services unless you have permission.

Why this matters

For a learning community, communication is part of diagnosis. Another contributor should be able to repeat the exact steps and understand which tests were performed. Avoid including passwords, tokens, patients’ records, private file paths or complete network inventories in public issue reports.

Chapter 25 — Users, groups and why identity matters

Bits to Banking · System Administration: From Zero · Umicom Foundation

Audience: first-time users and returning learners; practical examples appropriate for supervised younger learners.

Estimated study time: 45–65 minutes.

Prerequisites: Chapters 2 and 9.

Why this matters

A volunteer signs in to a shared training computer and sees that they can read a sample document but cannot install software. Another user can install software but cannot view the volunteer’s private files. Both outcomes may be correct. System administration begins by understanding which account is acting and what that account is permitted to do, rather than trying to make every operation work by elevating privileges.

What you will be able to do

By the end of this chapter you should be able to explain the new terms in ordinary language, select a safe read-only command for the right operating system, recognise a normal result and identify an unverified result. You should also be able to describe what permission would be needed before making a real system change.

The mental model

A user account answers “who is doing this?”. A group answers “which collection of users shares a permission?”. Authentication proves identity; authorisation checks whether that identity can take an action. A signed-in person can also start programs that run with another identity, such as a Windows service account or a Linux daemon. Do not confuse the visible account name with the privileges of every process. Windows also has a distinction between being a member of Administrators and actually running an elevated process under User Account Control (UAC). Linux commonly separates an ordinary account from controlled administrator actions performed with sudo.

How accounts become effective permissions

Imagine an online classroom with a teacher, a learner and an application server. The learner must read lessons and create documents in their own folder. The teacher may edit shared lessons, and a background publishing service may read approved Markdown material. These are three distinct roles, not three reasons to make every account a local administrator. The right question is “which operation must this identity perform on which resource?”. Identify the smallest privilege that satisfies that task.

In a multi-user environment, membership can change while a session remains active. A permission update may not immediately affect an already issued access token or group membership visible to a running process. This is one reason an access problem should be reproduced with the same user and session rather than tested only as an administrator. A Windows computer joined to a domain may also display domain identity information unavailable to the local account commands used in this lesson. Record the environment rather than assuming all Windows computers are identical.

Chapter 26 — Understand file permissions without opening private data

Bits to Banking · System Administration: From Zero · Umicom Foundation

Audience: first-time users and returning learners; practical examples appropriate for supervised younger learners.

Estimated study time: 50–75 minutes.

Prerequisites: Chapter 25 and Chapter 7.

Why this matters

A project README is visible in one folder but access is denied in another. A beginner may assume the file has disappeared. Often the file exists, but the operating system has correctly refused an operation. The administrator’s job is to explain access decisions without bypassing the owner or exposing private files.

What you will be able to do

By the end of this chapter you should be able to explain the new terms in ordinary language, select a safe read-only command for the right operating system, recognise a normal result and identify an unverified result. You should also be able to describe what permission would be needed before making a real system change.

The mental model

A folder path tells you where an item is; permissions decide who may read, write, or traverse it. Windows NTFS uses access-control lists (ACLs) with entries applying to users and groups. Rights may be inherited from the containing folder, and an explicit deny entry can influence access. Linux traditionally shows owner, group and other read/write/execute bits; directories use execute for traversal, so being able to read the directory name list is not the same as reaching a file. Additional ACL mechanisms and security layers can apply on either system. Never conclude “everyone can read” from one superficial permission view.

What “effective access” really asks

Consider a Notes project with a docs directory. On Linux, a file may be readable according to its own mode but still inaccessible if the user lacks traverse permission on a parent directory. On Windows, an inherited ACL entry might grant read access while another relevant identity or policy changes the overall result. File ownership may permit altering permissions but does not automatically imply every ordinary access request succeeds. The exact behaviour depends on the operating system and the file and share permission layers involved.

Do not test private documents to discover access rights. Use a file you own. The responsible administrator asks the owner of the resource to approve any change and documents the intended access policy before modifying ACLs. The goal is not to make an error disappear; it is to ensure only the people and services with a genuine need can use the resource.

Term Meaning
ACL An access-control list of permissions and identities.
Inheritance A child receiving permission rules from its parent.
Read Permission to inspect content, when other controls allow it.
Write Permission to change content or metadata.
Traverse Permission to pass through a directory to reach a child.

Chapter 27 — Investigate a Windows service and its event records

Bits to Banking · System Administration: From Zero · Umicom Foundation

Audience: first-time users and returning learners; practical examples appropriate for supervised younger learners.

Estimated study time: 45–70 minutes.

Prerequisites: Chapters 10–12.

Why this matters

An application window will not open. Restarting the entire computer might hide the problem temporarily, but it does not explain it. Windows has background services that support networking, software updates and many other functions. We will learn to inspect those services without stopping or reconfiguring them.

What you will be able to do

By the end of this chapter you should be able to explain the new terms in ordinary language, select a safe read-only command for the right operating system, recognise a normal result and identify an unverified result. You should also be able to describe what permission would be needed before making a real system change.

The mental model

A Windows service is a background program managed by the Service Control Manager. It has a configuration, an account, dependencies and a runtime status such as Running or Stopped. A process can exist while the service is unhealthy; a service can also be deliberately Stopped when not required. An event log records messages generated by Windows and applications. Look for a sequence: when was the last successful startup, what changed immediately before failure, and was the failure in the application, a dependency or access to a resource? Event timestamps are observations, not proof of causation.

Separate a service state from a user-visible outcome

A service manager reports lifecycle information: configured start type, process state and sometimes exit codes. A student needs to know whether an application can actually complete a task. These are different checks. A service can report Running while its database credentials are expired, its dependency is slow or its listener is on the wrong port. Likewise, a stopped Print Spooler is not evidence that a headless C23 test machine is faulty.

When reading events, limit the time range and choose a relevant provider if possible. A System log contains many unrelated messages. A useful support report records a specific user-visible failure at 10:12, then examines events immediately before and after 10:12 for the correct service. A timestamp without a matching process, machine and operation is context, not causation. Keep raw logs in an approved restricted location rather than pasting them into a public report.

The mental model

Why user services are different from system services

A desktop user may run a background synchronisation process attached to their login session. A server may run the same kind of process as a system unit using a dedicated service account. These lifetimes and permission boundaries are different. A command using systemctl --user asks the user service manager; a command without --user usually asks the system manager. Neither should be used to modify a service merely because its name sounds familiar.

The presence of systemctl does not guarantee systemd is PID 1. Some containers, rescue environments and distributions use different service managers, and a limited systemd instance may not have all journal facilities. Start by reading the environment. The mental model

Why this matters

A contributor wants to inspect a Linux test machine from a Windows laptop. Mixing those questions is a common source of security mistakes.

What you will be able to do

By the end of this chapter you should be able to explain the new terms in ordinary language, select a safe read-only command for the right operating system, recognise a normal result and identify an unverified result. The mental model

An SSH client contacts an SSH server over a network connection, commonly TCP port 22. The server presents a host key so the client can recognise the same server in future sessions. The client can authenticate with a password or user key pair, subject to server policy. A private key is secret and remains on your computer; a public key can be registered with authorised servers. The known_hosts file remembers server host keys. A changed host-key warning is a trust event requiring verification, not an inconvenience to suppress with StrictHostKeyChecking=no.

What a trustworthy first SSH connection looks like

Before connecting, the learner must know the hostname or address from a trusted administrator, their authorised username and the expected server host-key fingerprint. The host key may be new because the machine has never been contacted, but that does not make an unverified first connection automatically trustworthy. Once the administrator confirms the fingerprint independently, the client can establish a recorded identity for future connections.

An SSH public key file ending in .pub is intended to be distributed for authentication. The matching private key is not. Do not paste either into commands from a stranger who says it is required to repair GitHub authentication. You may see SSH used for Git transport (git@github.com:...) without ever opening an interactive server terminal; the same cryptographic trust concepts apply, but the permitted operations differ.

Chapter 31 — Diagnose DNS, TCP ports and firewall boundaries

Bits to Banking · System Administration: From Zero · Umicom Foundation

Audience: first-time users and returning learners; practical examples appropriate for supervised younger learners.

Estimated study time: 55–85 minutes.

Prerequisites: Chapters 15–16.

Why this matters

A browser says a learning website cannot be reached. The problem might be its name, the network route, the server process, its listening port or a security policy. A single failed test cannot reliably distinguish these possibilities. System administrators isolate one layer at a time.

What you will be able to do

By the end of this chapter you should be able to explain the new terms in ordinary language, select a safe read-only command for the right operating system, recognise a normal result and identify an unverified result. You should also be able to describe what permission would be needed before making a real system change.

The mental model

A hostname such as example.com is a human-friendly identifier. DNS translates names into addresses; the application then attempts a connection to a server address and port. A successful DNS lookup does not prove TCP reachability. A successful TCP connection does not prove that the HTTP service returns a correct application response. A ping refusal also does not prove that a web service is down because ICMP can be blocked. A firewall applies policy to traffic; it should never be disabled wholesale merely to “see if that fixes it”.

Make each network check answer only one question

Name resolution asks “which address should this name refer to?”. A TCP connection asks “did I reach an accepting endpoint on this port?”. An HTTPS request asks “did the web server negotiate transport security and return an application-level response?”. The three checks build on one another but cannot be substituted for each other. A successful TCP probe on 443 does not prove that the certificate is trusted, the application is authenticated or the requested page exists.

Be precise about localhost. 127.0.0.1 always refers to the same host network namespace that issued the request; it does not refer to your colleague’s machine. In containers or virtual machines, the localhost of one environment is often different from the host's localhost. An educational server bound to loopback should not be exposed externally just to make a remote demo work. Use approved routing and listen policies instead.

Chapter 32 — Understand disk space, filesystems and safe capacity checks

Bits to Banking · System Administration: From Zero · Umicom Foundation

Audience: first-time users and returning learners; practical examples appropriate for supervised younger learners.

Estimated study time: 45–70 minutes.

Prerequisites: Chapters 13–14.

Why this matters

A training application fails to save a file. Before touching configuration, check whether the destination exists, whether the user can write there and whether sufficient storage is available. Disk capacity is a finite resource, and different storage layers can fail for different reasons.

What you will be able to do

By the end of this chapter you should be able to explain the new terms in ordinary language, select a safe read-only command for the right operating system, recognise a normal result and identify an unverified result. You should also be able to describe what permission would be needed before making a real system change.

The mental model

A physical disk stores data, while a partition or volume describes a managed region. A filesystem organises files and directories within a volume. Windows frequently uses NTFS and drive letters; Linux often mounts filesystems at directories such as /home and /var. Free space is different from free inodes on some filesystems: a Linux volume can have available bytes but run out of metadata entries. A disk can have free space and still produce I/O errors. Reading filesystem information is a safe first step; formatting, repartitioning or repairing a device is not part of this beginner course.

Why administrators treat available space as evidence, not a repair instruction

A file save can fail because the filesystem is full, but the same symptom may come from permissions, a stale path, locked files or quota rules. When a compiler prints “no space left”, identify the exact output path and mount point before clearing anything. Build directories contain reproducible artefacts, yet they can also contain logs and diagnostic evidence important to an investigation. Removing a build folder without review may make the original failure impossible to reproduce.

Storage reports can also differ across tools. Free disk blocks, available blocks for ordinary users, filesystem quota and cloud-drive availability are not necessarily the same quantity. A percent utilisation indicator is an overview, not an exact promise that a particular file can be written. System administrators keep the measurements alongside the workload and timestamp.

Chapter 33 — Backups, restore drills and proving that recovery works

Bits to Banking · System Administration: From Zero · Umicom Foundation

Audience: first-time users and returning learners; practical examples appropriate for supervised younger learners.

Estimated study time: 60–90 minutes.

Prerequisites: Chapter 14 and Chapter 7.

Why this matters

A backup file exists, but does it contain the latest version? Can it actually be opened? A backup strategy is useful only when a restore can be demonstrated. In this practical exercise we will make a copy of your own harmless training README and restore that copy to a separate test location.

What you will be able to do

By the end of this chapter you should be able to explain the new terms in ordinary language, select a safe read-only command for the right operating system, recognise a normal result and identify an unverified result. You should also be able to describe what permission would be needed before making a real system change.

The mental model

The common 3-2-1 planning heuristic describes three copies of important data, on two types of storage, with at least one copy elsewhere. It is not a substitute for considering encryption, retention, access controls, immutable copies or ransomware. A backup is a recoverable copy; a restore drill proves whether it can be used; a hash helps compare exact bytes. A matching SHA-256 digest of two files is strong evidence that their contents match, but it does not prove the backup job had permission to capture every required file or that a complete application can be restored.

The difference between a safe sample restore and disaster recovery

In this lesson the restored file is a Markdown README. That is deliberate. A banking ledger, medical record system or live treasury service may store interconnected files, transaction logs and databases. Copying only one database file while the server is changing it can create an inconsistent backup. Production recovery needs application-aware snapshots, tested dependencies, security controls and a documented sequence to return the complete service safely.

The training drill also protects the previous copy. We first check whether the destination exists, then copy the practice file, then hash both copies, then restore to a third location. These stages are observable and reversible. A good restore runbook names the original source, backup location, restore destination and result of a meaningful application-level check. The very first lesson for a beginner is that verifying a backup means testing what can be recovered—not merely counting backup files.

Chapter 34 — Protect credentials, use MFA and practise least privilege

Bits to Banking · System Administration: From Zero · Umicom Foundation

Audience: first-time users and returning learners; practical examples appropriate for supervised younger learners.

Estimated study time: 45–70 minutes.

Prerequisites: Chapters 9, 19–20 and 25.

Why this matters

The most expensive mistake in an introductory Git lesson is not a syntax error: it is accidentally sharing a password or token in a repository, screenshot or support log. Good administration treats credentials as secrets from the beginning.

What you will be able to do

By the end of this chapter you should be able to explain the new terms in ordinary language, select a safe read-only command for the right operating system, recognise a normal result and identify an unverified result. The mental model

A password is one authentication factor; a hardware authenticator or app-based challenge can provide an additional factor. Multi-factor authentication (MFA) reduces the risk of a stolen password being enough to sign in. A personal access token, SSH private key and API secret are all credentials even when they do not look like a password. Least privilege applies to humans and background services. Permission to administer a computer is separate from permission to access customer, patient or colleague data. Rotating a token after exposure is necessary, but repository history may still contain the leaked value and must be remediated according to project policy.

Where secrets accidentally leak during ordinary development

A shell command can reveal sensitive information in its arguments, console history, screenshots, diagnostic logs or copied support transcripts. A repository can preserve deleted lines inside Git history even after the working file looks clean. This is why we do not store secrets.env, personal access tokens, credentials or recovery codes in tracked source files. Template files may describe required variable names, but should never contain production values.

A properly delegated task should also limit what the account can do. A classroom contributor needs permission to edit a documentation fork, not to administer a production Linux server or view beneficiaries’ personal records. An Umicom application that needs to read published lessons should not automatically receive write access to security configuration. Security works best when permissions and ownership are designed before an incident forces emergency changes.

Chapter 35 — Read system metrics, logs and an incident timeline

Bits to Banking · System Administration: From Zero · Umicom Foundation

Audience: first-time users and returning learners; practical examples appropriate for supervised younger learners.

Estimated study time: 50–80 minutes.

Prerequisites: Chapters 12, 23 and 27.

Why this matters

At 09:00 a build starts. At 09:02 disk space drops. At 09:03 the linker fails. At 09:04 a service reports an error. Which event caused the failure? An experienced administrator gathers evidence in order rather than assuming the latest visible warning is the root cause.

What you will be able to do

By the end of this chapter you should be able to explain the new terms in ordinary language, select a safe read-only command for the right operating system, recognise a normal result and identify an unverified result. You should also be able to describe what permission would be needed before making a real system change.

The mental model

Observability means understanding a system from useful signals. Metrics are measurements such as available memory or request rate. Logs are event records containing timestamps and context. Traces describe the path of one operation across components. These signals are complementary: high CPU is not itself an error, and a log entry that says ERROR may describe an issue unrelated to the incident. Always record the time zone, host, process and source revision, because an event from yesterday’s version cannot prove today’s build behaviour.

How to avoid reading the wrong evidence

Metrics answer questions about quantities; logs record discrete events; traces connect work across components. A high number of log entries may be completely normal during build progress, while one concise linker error can block the entire application. The responsible investigator narrows the time window, searches for the first failing stage, and keeps a reference to the original raw output when permitted. Compiler warnings and test outcomes should be attributed to the exact CMake preset and source revision that produced them.

If two machines use different time zones, their “09:00” events may not be simultaneous. Prefer timestamps with offsets and note clock synchronisation. Also protect privacy when sharing diagnostic artefacts. A useful report can say “the service failed to read an expected config file at 14:03 UTC” without publishing the contents of the private configuration or the username in its path.

Log A recorded event with context and timestamp.

Root cause The underlying factor whose correction prevents recurrence.

Worked Umicom support scenario

A classroom worksheet supplies these fictional facts: (a) the Notes window exists, (b) its document storage is not accessible, (c) an old backup from a previous session has a matching hash, and (d) no current save-and-read test was performed. The correct outcome is BLOCKED. A running window and an old backup cannot substitute for current storage and application readiness checks. The learner writes a recovery proposal: verify permissions and storage, restore to a separate review location if approved, then rerun the actual Notes operation.

A disciplined investigation sequence

  1. Describe the symptom precisely. Identify what failed and the expected result.
  2. Identify the environment. Record current account, machine class, working directory and observation time; redact private identifiers.
  3. Run the smallest relevant read-only check. Choose evidence that distinguishes two possible causes.
  4. Compare results with the requirement. Missing, blocked or outdated checks are not successful checks.
  5. Separate fact and interpretation. Label hypotheses explicitly.
  6. Propose, do not silently apply, a change. State approval, effect, rollback and validation criteria.

Common mistakes and how to respond

Incorrect assumption Better engineering response
A successful backup hash proves the application is now ready. Backup integrity and current service readiness are distinct; the former may not establish the latter.
Git status is clean, so the failure is resolved. Version-control cleanliness does not prove runtime correctness or tests.
A missing test should be recorded as passed to complete the checklist. A missing required test blocks the claim. An honest NOT RUN is better than false assurance.

Stage 3 Instructor Guide — Practical Infrastructure

Safe teaching environment

  1. Use a normal, non-elevated Windows PowerShell 7 shell or an authorised Linux account. If access to a command is restricted, teach the meaning of that refusal.

  4. Screenshots should show only relevant fields. Redact usernames, hostname and network information before sharing outside the device.

Two-route delivery

The objective is not memorisation.
