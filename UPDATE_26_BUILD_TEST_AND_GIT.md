This update changes **only** the Bits2Banking educational repository at `C:\umicom\Umicom-Bits2Banking`. It adds no Framework, Kernel, OS or Umicom Applications source changes.

Preserve unrelated local modifications.

## 2. Build the web-server laboratory (PowerShell)

```powershell
Set-Location "C:\umicom\Umicom-Bits2Banking"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"

cmake -S ".\labs\native\http-loopback-server" `
    -B ".\output\learning-build\http-loopback-server" `
    -G Ninja `
    -DCMAKE_C_COMPILER="C:\msys64\ucrt64\bin\gcc.exe" `
    -DBUILD_TESTING=ON
if ($LASTEXITCODE -ne 0) { throw "CMake configuration failed" }

cmake --build ".\output\learning-build\http-loopback-server" --parallel 2
if ($LASTEXITCODE -ne 0) { throw "C23 build failed" }
```

The build target is `btb-http-server.exe`. The existing `btb_http` static library now also includes the routing, response-progress and educational handler implementations.

## 3. Run all tests

```powershell
ctest --test-dir ".\output\learning-build\http-loopback-server" `
    --output-on-failure
if ($LASTEXITCODE -ne 0) { throw "One or more HTTP tests failed" }
```

**Expected: 11/11 tests passing.** The original six CTests remain active. Five new cases cover exact route dispatch, refusal of stopping inside a handler, 4,096 malformed path registrations, counted GET/HEAD responses and incomplete transfers.

To run only the new tests:

```powershell
ctest --test-dir ".\output\learning-build\http-loopback-server" `
    -R "bits2banking.http.(routing|service_lifetime|route_mutations|response_completion|disconnect_semantics)" `
    --output-on-failure
```

## 4. Preview a combined static site and C23 API

Start the server in one terminal:

```powershell
Set-Location "C:\umicom\Umicom-Bits2Banking"
$Root = (Resolve-Path ".\labs\native\http-loopback-server\sample_site").Path

& ".\output\learning-build\http-loopback-server\btb-http-server.exe" `
    --port 8765 --root $Root --routes
```

In a **second** PowerShell terminal:

```powershell
Invoke-RestMethod "http://127.0.0.1:8765/api/courses"
Invoke-WebRequest "http://127.0.0.1:8765/api/courses" -Method Head
Invoke-WebRequest "http://127.0.0.1:8765/assets/site.css" -Method Get
```

Open `http://127.0.0.1:8765/routing-guide.html` in a browser. The first endpoint returns JSON from a registered C23 function; the stylesheet and routing-guide page are files from the read-only root. The HEAD response has no body. Stop the listener with **Ctrl+C**. If port 8765 is already occupied, stop the existing server or choose another port in the range 1024–65535.

With `--routes` omitted, the server retains the Update 25 static-file behaviour. With both `--routes` and `--root` omitted, it retains the original fixed responses.

The website is still generated by the existing MkDocs installation. This batch introduces **no new Python implementation files**.

```powershell

& ".\.venv\Scripts\python.exe" -m mkdocs build --strict
```

`Test-Path` should return `True`. Visit the site using the native C23 server and a `--root` pointing at `C:\umicom\Umicom-Bits2Banking\site`. Validate the Islam volume, chapters 1–161 and the new routing video scripts in the navigation. The published website has separate asset- and page-size considerations; this learning server remains limited to 64 MiB per individual file and a bounded connection deadline.
