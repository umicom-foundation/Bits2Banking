## Framework — C23 build and tests

```powershell
Set-Location "C:\umicom\Umicom-Applications"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"

cmake -S ".\framework\tools\umicom-education" `
    -B ".\build\umicom-education" `
    -G Ninja `
    -DCMAKE_C_COMPILER="C:\msys64\ucrt64\bin\gcc.exe" `
    -DBUILD_TESTING=ON

cmake --build ".\build\umicom-education" --parallel 2
ctest --test-dir ".\build\umicom-education" --output-on-failure
```

The standalone Framework Education project now registers **10 tests**, including `framework.education.binary_inspect` and `framework.education.binary.cli`.

Inspect just the new tests:

```powershell
ctest --test-dir ".\build\umicom-education" `
    -R "^framework\.education\.binary" -V
```

A successful binary test includes a generated COFF file stored temporarily at a path containing spaces. The test deletes its own fixture. No root repository code is removed.

## Inspect one ordinary COFF object

Look inside the laboratory's configured build directory for `catalogue.c.obj` (or `.o`). The exact subdirectory is generated by CMake and Ninja. To locate it:

```powershell
Get-ChildItem ".\output\learning-build\course-catalogue-library" `
    -Recurse -File -Include "catalogue.c.obj", "catalogue.c.o"
```

Copy the reported path and pass it to the Framework command:

```powershell
Set-Location "C:\umicom\Umicom-Applications"
& $Education binary --file "PASTE_THE_OBJECT_PATH_HERE"
```

Expected format for a GCC UCRT64 object: **COFF**. The command is read-only; it does not execute the object.
